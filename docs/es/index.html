Prólogo

Por qué un lenguaje pequeño

Blizzard existe para construir programas útiles con menos ceremonias. Es un lenguaje pequeño e interpretado: booleanos, números, cadenas, listas, diccionarios, funciones y módulos son casi todo lo que tiene, y casi todo el mundo exterior se alcanza a través de un módulo que cargas con using.

Este libro explica todo el lenguaje, de forma completa y explícita. Cada valor, cada operador, cada función incorporada, cada módulo y cada herramienta se describe con su comportamiento exacto y al menos un ejemplo verificable. Cuando una regla es sutil — la división que siempre devuelve un flotante, un respaldo que solo actúa sobre nil, condiciones que deben ser booleanos reales — se dice en voz alta en lugar de dejarlo a la intuición.

La mejor manera de leerlo es con el intérprete abierto. Todos los listados de este libro están pensados para ejecutarse. Escríbelos, ejecútalos, cámbialos, rómpelos y lee lo que dice el error: los errores de Blizzard señalan la línea, la columna y la construcción exacta.

1 · Orientación

Empieza aquí

Un programa de Blizzard es un archivo de texto que se lee de arriba a abajo. Las sentencias asignan valores, llaman funciones, importan módulos, definen funciones o controlan la ejecución. Los bloques modernos usan llaves; la forma indentada anterior sigue aceptándose durante la migración.

Aviso experimental. Blizzard es un proyecto de investigación asistido por IA. La sintaxis, las API, los formatos de paquetes y la estructura interna pueden cambiar bruscamente entre versiones. Fija las versiones y no trates 0.2 como un contrato de estabilidad para producción.

Migración de Snow a Blizzard: Snow 0.1 usaba archivos .snow, snowman y snow.toml. Blizzard 0.2 usa .blizz, blizzard y blizzard.toml. El código nuevo usa bloques con llaves, let e import.

Sintaxis Blizzard 0.2. Los programas nuevos usan let, import y bloques delimitados por llaves. Los saltos de línea separan sentencias dentro de un bloque; los puntos y coma siguen disponibles para varias sentencias en una línea. 
import json
let name = "Ada"
fn greet(value) {
    if value != "" {
        print(json.stringify(value))
    }
}
greet(name)

1.1Tu primer programa

Guarda este archivo como hello.blizz:

Ejecútalo con el comando blizzard:

blizzard hello.blizz

print escribe sus argumentos en la terminal, separados por un espacio y seguidos de un salto de línea. La segunda línea asigna la cadena "blizzard" al nombre name. La tercera línea concatena dos cadenas con + e imprime Running: blizzard.

1.2Experimentar en el REPL

El REPL lee una sentencia cada vez, la evalúa e imprime el resultado.

blizzard repl

Dentro verás el prompt blizzard>. Escribe 2 + 2, pulsa Enter y responderá 4 con un tinte amarillo. Un encabezado de bloque, como el de abajo, mantiene el prompt abierto hasta que termines el bloque con una línea en blanco; la sangría se añade por ti.

blizzard> pub fn cal(a, b):
...>     for i in range(a, b):
...>         print(i * 2)
...>
0
2

La línea en blanco cierra el bloque y el cuerpo de la función se ejecuta. Para un experimento rápido sin guardar un archivo, también puedes evaluar una cadena directamente:

blizzard eval 'print("hi")'
blizzard -e 'print(6 * 7)'

1.3Leer los errores

Los errores son precisos. Un error de análisis muestra el archivo, la línea, la columna y un caret bajo el carácter que lo provoca:

examples/test.blizz:2:1: error: expected an indented block after the 'fn' statement
    fn add(a, b):
    ^

El mensaje nombra el archivo, la línea y la columna después del número de línea, te dice exactamente lo que el analizador esperaba e imprime la línea culpable con un caret en la posición del error. Los errores en tiempo de ejecución llevan el archivo, la línea, la columna y — si no se capturan — un rastro de pila.

1.4La estructura de un proyecto, de un vistazo

Para algo más grande que un archivo suelto, sigue la convención: el código fuente en src/, las pruebas en archivos cuyo nombre termine en _test.blizz y la configuración en blizzard.toml. Ejecuta un proyecto completo con blizzard run, que elige src/main.blizz automáticamente.

blizzard init my_app
cd my_app
blizzard run

Cada pieza se explica en profundidad en el capítulo 14.

2 · Diseño

El modelo del lenguaje

Blizzard sigue un breve pipeline de ejecución: tokenizar, analizar, comprobar, compilar, interpretar. Cada etapa tiene exactamente un trabajo y cada fallo lleva una ubicación precisa. Entender este pipeline te ayudará a interpretar los errores que veas.

  • Tokenizador. Convierte el texto fuente en tokens. La sangría, los números, las cadenas, las f-strings y los operadores son su responsabilidad.
  • Analizador. Construye el árbol del programa. Sus errores significan que el texto no pudo convertirse en un programa en absoluto — estos son los errores más comunes para principiantes.
  • Comprobador. Inspecciona nombres, tipos, módulos y código inalcanzable sin ejecutar el programa. Es el análisis estático que hay detrás de blizzard check y de los diagnósticos del editor.
  • Compilador. Emite operaciones para una máquina virtual.
  • Intérprete. Ejecuta las operaciones. Los fallos en tiempo de ejecución se informan con la ubicación en el código y, si no se capturan, llevan un rastro de pila.

2.1Dinámico por defecto

Los nombres no necesitan anotaciones. La misma variable puede contener un entero y luego una cadena. Los tipos no son decoraciones opcionales de un contrato fijo: son graduales. Puedes añadir anotaciones en las fronteras donde un contrato tiene valor, y Blizzard las comprueba en tiempo de ejecución.

value = 10
value = "now a string"

2.2Valores en lugar de clases

No hay clases. Las listas, los diccionarios, las funciones, los módulos y los valores nativos se combinan directamente, y los datos siempre están a la vista: un diccionario es el registro, una lista es la secuencia, una función es el comportamiento.

2.3Efectos explícitos

El acceso a la red, los archivos, los procesos y el entorno viven en módulos (http, fs, sys). Un programa que toca el mundo exterior tiene que decirlo. Esto mantiene los efectos secundarios visibles y hace los scripts predecibles.

2.4Análisis estático sin ejecutar

Como el comprobador nunca ejecuta el código, blizzard check file.blizz informa de nombres indefinidos, variables sin usar, código inalcanzable, módulos desconocidos y desajustes de tipo de forma instantánea y segura — sin llamadas de red ni cambios de archivos.

3 · El texto

El texto fuente

Este capítulo cubre la materia prima de un programa de Blizzard: comentarios, nombres, palabras clave, sangría, números y las tres maneras de escribir una cadena.

3.1Comentarios

Un comentario empieza con # y llega hasta el final de la línea. Los comentarios se ignoran y pueden aparecer después del código.

# un comentario de línea completa
count = 1  # un comentario al final

3.2Nombres y palabras clave

Los nombres contienen letras, dígitos y guiones bajos, y no pueden empezar por un dígito. Se permiten letras Unicode en los nombres. Los nombres distinguen mayúsculas: count y Count son variables distintas.

Las siguientes palabras están reservadas y no pueden usarse como nombres:

using import pub priv const as
fn return if elif else for in where while break continue
and or not try catch always match case with

Esa es la lista completa de palabras clave. true, false y nil son valores, no palabras clave.

3.3Sangría y diseño

Los bloques empiezan después de dos puntos y usan cuatro espacios de sangría. Las líneas con la misma sangría forman un bloque; un cambio de sangría abre o cierra bloques. Un bloque con sangría también puede aparecer en la misma línea después de los dos puntos.

fn double(x): x * 2
if ready: print("go")

Un punto y coma puede separar sentencias en una misma línea:

a = 1; b = 2; print(a + b)

Las expresiones largas pueden continuar dentro de ( ), [ ], { } y ?[ sin un carácter de continuación.

3.4Números

Los enteros pueden escribirse en decimal o en otra base. Los flotantes llevan un punto decimal y pueden terminar en uno.

decimal     = 42
binary      = 0b1010
octal       = 0o17
hexadecimal = 0xFF
float_value = 3.14
trailing    = 9.

Las bases también aceptan prefijos en mayúsculas (0X, 0B, 0O). Un dígito inválido para la base es un error, así que 0b102 y 0o8 no se analizan.

3.5Cadenas

Las comillas dobles y simples son equivalentes. Los únicos escapes son \n (salto de línea), \t (tabulador), \r (retorno de carro), \\ (barra invertida), \" y \'. Cualquier otra secuencia con barra invertida es un error.

a = "double"
b = 'single'
c = "line one\ntab\there"

3.6Cadenas entre triples comillas

Las cadenas entre triples comillas pueden ocupar varias líneas y conservan sus saltos de línea.

poem = """
On the blizzard
a single line
of code.
"""

3.7F-strings

Una f antes de la comilla de apertura crea una f-string: {expresión} dentro se evalúa y su resultado se inserta. Las llaves se anidan contando profundidad, así que f"{ {a: 1} }" funciona. Usa {{ y }} para llaves literales. Combina f con triples comillas para interpolar en varias líneas.

user = "Ada"
age = 36
print(f"Hello, {user}!")
print(f"{user} is {age} years old.")
print(f"Curly: {{ {user} }}")

La salida es Hello, Ada!, luego Ada is 36 years old. y luego Curly: { Ada }. Las f-strings funcionan con comillas dobles, simples y triples (f"…", f'…', f"""…""").

4 · Los sustantivos

Valores

Todo en Blizzard es un valor. Hay diez clases: nil, booleanos, enteros, flotantes, cadenas, listas, diccionarios, funciones, módulos y valores nativos. Este capítulo define cada uno con precisión.

4.1nil

nil representa la ausencia. No es un error por sí mismo: las funciones pueden devolverlo, y los operadores nullish lo tratan de forma especial. Una variable de entorno sin definir, una clave de diccionario ausente bajo acceso seguro y un first con resultado vacío producen nil.

4.2Booleanos, enteros y flotantes

on = true
off = false
n = 42
p = 3.14159

Los enteros son números enteros de ancho arbitrario. Los flotantes son dobles IEEE-754. Un entero y un flotante son iguales cuando tienen el mismo valor: 1 == 1.0 es true.

4.3Cadenas

Las cadenas son secuencias de caracteres y se indexan por carácter, no por byte. Los índices negativos cuentan desde el final. El corte usa rangos semiabiertos [start:end] y respeta caracteres Unicode.

s = "hello"
print(s[1])      # e
print(s[-1])     # o
print(s[1:4])    # ell
print(len(s))    # 5

Los ayudantes de cadena se pueden llamar como funciones o métodos: upper(s) y s.upper() son equivalentes. La forma de método también funciona con lower, trim, split, join, replace, contains y los demás ayudantes de cadena.

4.4Listas

Las listas guardan cualquier valor en orden. Son mutables: puedes asignar a través de un índice. La indexación admite negativos y cortes, igual que las cadenas.

items = [10, 20, 30]
print(items[0])   # 10
print(items[-1])  # 30
print(items[1:])  # [20, 30]
items[1] = 99     # muta en el lugar
print(items)      # [10, 99, 30]

Una lista puede contener tipos mezclados y otras listas:

mix = [1, "two", [3, 4], {"five": 5}]

4.5Diccionarios

Un diccionario asocia claves con valores y recuerda el orden de inserción. En los literales, las claves pueden escribirse sin comillas. Accede a un atributo con un punto, a una clave con corchetes, asigna claves nuevas libremente e itera en orden de inserción.

config = {"theme": "dark"}
config.timeout = 30
config["region"] = "us"
print(config)             # {theme: dark, timeout: 30, region: us}
print(config.theme)       # dark
print(config["timeout"])  # 30

Leer una clave que no existe con acceso normal es un error: config.nope lanza key not found: nope. Para leer datos opcionales de forma segura usa los operadores nullish y de acceso seguro del capítulo 5, o get(config, "nope"), que devuelve nil.

4.6Funciones, módulos y valores nativos

Las funciones son valores que defines con fn o escribes como lambdas (capítulo 7). Los módulos son espacios de nombres que devuelven using e import (capítulo 10). Los valores nativos son objetos que proporciona el anfitrión, como el store que devuelve db.open (capítulo 12) y las respuestas HTTP.

4.7Conocer el tipo

type(x) devuelve la clase de un valor como una cadena. Los nombres posibles son: nil, bool, int, float, str, list, dict, fn, module, native y response.

print(type(42))       # int
print(type([1, 2]))   # list
print(type({}))       # dict
print(type(nil))      # nil

4.8Cómo se imprimen los valores

print muestra los valores directamente. Las listas se imprimen como [a, b], los diccionarios como {key: value}, y el contenido de las cadenas dentro de colecciones se imprime sin comillas.

print(["a", "b"])              # [a, b]
print(keys({a: 1}))            # [a]
print({"name": "blizzard", "n": 2})# {name: blizzard, n: 2}

Los flotantes se imprimen en la forma más corta que conserva el valor: 3.5, 0.2, 2.5.

5 · Los verbos

Operadores

Los operadores combinan valores en expresiones. Blizzard usa palabras para la lógica (and, or, not, in) y símbolos para la aritmética, las comparaciones y el manejo de nullish. Este capítulo es la especificación precisa.

5.2Aritmética

print(7 + 2)   # 9
print(7 - 2)   # 5
print(7 * 2)   # 14
print(7 / 2)   # 3.5   (nunca es división entera)
print(7 // 2)  # 3     (división entera con piso)
print(7 % 2)   # 1

La división con / siempre devuelve un flotante: 7 / 2 es 3.5, no 3. Usa // para la división con piso. El operador módulo % toma el signo del dividendo: -7 % 2 es 1, y -7 // 2 es -4 (piso, no truncamiento).

El operador de potencia es asociativo por la derecha y nunca sorprende:

print(2 ** 10)    # 1024
print(2 ** 3 ** 2)# 512   (2 ** (3 ** 2))
print(2 ** 0.5)   # 1.4142135623730951

+ concatena cadenas, pega listas y fusiona diccionarios; * repite cadenas un número no negativo de veces.

print("blizzard" + "fall")   # blizzardfall
print("ab" * 3)          # ababab
print([1, 2] + [3])      # [1, 2, 3]

5.3Comparaciones

Las comparaciones funcionan sobre números (los enteros y los flotantes son comparables entre sí), cadenas (lexicográfico) y booleanos (false es menor que true). Las cadenas de comparaciones se evalúan tal como se leen:

print(1 < 2 and 2 < 3)   # true
print(3 >= 3)             # true
print("abc" < "abd")      # true

La igualdad es profunda: las listas y los diccionarios se comparan valor a valor. Mezclar clases incomparables lanza un error: usa type() para comprobar primero si tienes dudas.

5.4Lógica y pertenencia

print(true and false)     # false
print(not false)          # true
print("ow" in "blizzard")     # true  (subcadena)
print(3 in [1, 2, 3])     # true  (pertenencia en lista)
print("x" not in {a: 1})  # true  (prueba de clave en diccionario)
print(false or 2 == 2)    # true

and y or hacen cortocircuito: el segundo operando solo se evalúa si hace falta. También exigen que ambos operandos sean booleanos. in y not in son operadores de comparación: subcadena en cadenas, pertenencia profunda en listas, prueba de clave en diccionarios y módulos.

5.5Nullish: ?? y ??=

?? devuelve su lado derecho solo cuando el izquierdo es nil. El cero y false pasan intactos. ??= asigna el lado derecho solo si el izquierdo es nil.

x = nil
print(x ?? "fallback")    # fallback
print(0 ?? "nope")        # 0
print(false ?? "nope")    # false
x ??= "assigned"
print(x)                  # assigned

5.6Acceso seguro: ?. y ?[

El acceso normal lanza un error ante una clave que falta o un índice fuera de rango. El acceso seguro devuelve nil en su lugar, y una cadena se detiene en el primer valor ausente:

user = {name: "ada"}
print(user?.name)     # ada
print(user?.age)      # nil
print(user?.a?.b)     # nil   (la cadena se detiene antes)
items = [1, 2, 3]
print(items?[9])      # nil
print(items?[1])      # 2

Los operadores nullish y de acceso seguro trabajan juntos de forma natural para datos opcionales: user?.email ?? "no email".

5.7El operador ternario

La expresión condicional se lee value if condition else other. Solo se evalúa la rama elegida.

active = true
status = "on" if active else "off"
print(status)          # on

5.8Asignación compuesta

Los operadores de asignación aumentada += -= *= /= //= %= ??= aplican el operador y guardan el resultado de nuevo en un único nombre.

n = 100
n += 20     # 120
n *= 2      # 240
n //= 7     # 34
print(n)    # 34
6 · Dar significado a los nombres

Asignaciones y desestructuración

La asignación vincula un valor con un nombre. Blizzard ofrece asignación simple, asignación múltiple, asignación con tipo, constantes, desestructuración y asignación a través de atributos o índices. Cada una tiene una forma específica.

6.1Asignar un valor

count = 1
name = "blizzard"

6.2Asignar varios nombres a la vez

Escribe varios nombres a la izquierda y el mismo número de valores a la derecha:

a, b = 1, 2
print(a, b)      # 1 2

apple, banana = banana, apple   # intercambia en un solo paso

6.3Asignación con tipo

Un nombre puede llevar un tipo que Blizzard comprueba en tiempo de ejecución: name: type = value. Los tipos admitidos son int, float, str, bool, dict, list, nil, any, uniones como int|float y listas con tipo como str[].

age: int = 30
names: str[] = ["Ada", "Linus"]
either: int|float = 1.5

age = "thirty"           # error en tiempo de ejecución: expected int, received str

Una lista con tipo comprueba cada elemento en tiempo de ejecución:

nombres: str[] = ["Julian", "Ana"]
nombres = ["Julian", 5]  # error: element 1: expected str, received int

6.4Constantes

const marca un nombre como inmutable. Reasignarlo lanza un error en tiempo de ejecución.

const PORT = 8080
PORT = 9000    # error: const cannot be reassigned

6.5Desestructurar listas

Desempaqueta un solo valor en varios nombres con patrones de corchetes:

[first, second] = [10, 20]
print(first, second)      # 10 20

head, rest = [1, 2, 3]    # el patrón se ajusta a lo que hay
print(head)               # 1
print(rest)               # 2  (rest es el segundo elemento)

Una coma final o nombres de más manejan la cola:

[a, b, c] = [1, 2, 3, 4]  # ignora el resto
print(a + b + c)            # 6

6.6Desestructurar diccionarios

Las llaves extraen claves nombradas de un diccionario:

point = {x: 10, y: 20}
{x, y} = point
print(x, y)      # 10 20

6.7Asignar a través de atributos e índices

Puedes colocar un valor a través de una clave de diccionario o un índice de lista.

config = {}
config.theme = "dark"
config["timeout"] = 30

values = [1, 2, 3]
values[0] = 99
values[-1] = 33
print(values)      # [99, 2, 33]
print(config)      # {theme: dark, timeout: 30}

Las claves de diccionario deben ser cadenas; los índices de lista deben ser enteros, y los negativos cuentan desde el final.

7 · Bloques de construcción

Funciones

Las funciones son valores. Puedes definir una función con nombre, escribir una función anónima como expresión, guardar funciones en listas y diccionarios, pasarlas a ayudantes de orden superior y dejar que cierren sobre los nombres que las rodean.

7.1Funciones con nombre

Un bloque fn vincula un nombre. Sin un return, la función devuelve nil.

fn greet(name):
    return "Hello, " + name

print(greet("Ada"))    # Hello, Ada

7.2Parámetros y tipos de retorno

Los tipos son opcionales y se comprueban en tiempo de ejecución, tanto en los argumentos de entrada como en el valor de salida:

fn repeat(word: str, times: int) -> str:
    return word * times

fn add(left: int, right: int) -> int:
    return left + right

print(add(2, 3))       # 5
print(repeat("ab", 3)) # ababab

Un desajuste como add("x", 3) falla en tiempo de ejecución indicando el nombre y los tipos. Los parámetros sin tipo siguen siendo dinámicos.

7.3Funciones anónimas

double = fn(value): value * 2
print(double(21))      # 42

fn apply(f, x):
    return f(x)

print(apply(double, 21))   # 42

Una función anónima con una sola expresión puede escribirse en una línea después de los dos puntos. Un cuerpo largo usa un bloque.

7.4return y varios valores

return solo devuelve nil. Una función puede devolver varios valores.

fn split_point():
    return 10, 20

x, y = split_point()
print(x, y)    # 10 20

7.5Closures

Una función captura los nombres que la rodean en el punto donde se crea.

minimum = 10
is_large = fn(value): value >= minimum
print(is_large(5))    # false
print(is_large(50))   # true

7.6Recursión

fn fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(10))    # 55

La profundidad de la recursión está protegida por un límite; la recursión profunda e infinita se detiene con un error en lugar de reventar el anfitrión.

7.7Ayudantes de orden superior

map transforma cada elemento, filter conserva los que cumplen un predicado y fold reduce una lista. Para fold, el acumulador puede ir antes o después de la función: fold(list, acc, fn) o fold(fn, acc, list).

fn double(n): n * 2
fn is_even(n): n % 2 == 0
fn add(a, b): a + b

numbers = [1, 2, 3, 4]

print(map(double, numbers))    # [2, 4, 6, 8]
print(filter(is_even, numbers))# [2, 4]
print(fold(numbers, 0, add))   # 10
print(fold(add, 0, numbers))   # 10

Las funciones de orden superior también son un encaje natural para lambdas:

names = ["ada", "linus", "grace"]
shouts = map(fn(n): upper(n), names)
print(shouts)    # [ADA, LINUS, GRACE]

8 · Decisiones y bucles

Control de flujo

El control de flujo dobla el orden de ejecución. Blizzard elige entre ramas con if y match, repite con for y while, y deja que break y continue dirijan los bucles con precisión. Hay una regla que merece decirse dos veces: las condiciones deben ser booleanos reales — varios operadores exigen true o false, no valores que "sean como verdaderos".

8.1if, elif y else

score = 85

if score >= 90:
    grade = "A"
elif score >= 70:
    grade = "B"
else:
    grade = "C"

print(grade)    # B

Cada rama es un bloque. La condición entre if y los dos puntos debe evaluarse a un booleano.

8.2match y case

match compara un valor contra los casos de arriba a abajo y ejecuta el primero que coincida. Un caso puede enumerar varios valores. El comodín _ debe estar solo en su caso y debe ir el último.

command = "stop"

match command:
    case "start", "go":
        print("starting")
    case "stop":
        print("stopping")
    case _:
        print("unknown")

# imprime: stopping

8.3Bucles for

Un único nombre itera los elementos: los valores de una lista, las claves de un diccionario, los caracteres de una cadena (por carácter Unicode) o los números de un rango.

for x in [10, 20, 30]:
    print(x)

for key in {"a": 1}:
    print(key)        # a

for ch in "blizzard":
    print(ch)         # s n o w (cada uno en su línea)

for i in range(3):
    print(i)          # 0 1 2

range(start, stop, step) solo acepta enteros. stop es exclusivo; el paso puede ser negativo y nunca puede ser cero.

8.4Iteración con dos nombres

Dos nombres reciben pares: índice y valor para listas y cadenas, clave y valor para diccionarios. Para llegar a los pares que producen enumerate o zip, iterálos y desestructura con [primero, segundo] = par.

for index, value in ["a", "b"]:
    print(index, value)
# 0 a
# 1 b

for key, value in {"x": 1}:
    print(key, value)
# x 1

for pair in enumerate(["a", "b"]):
    [i, v] = pair
    print(i, v)
# 0 a
# 1 b

8.5Filtrar con where

where pegado a un for salta los elementos que no cumplen la condición antes de que el cuerpo se ejecute.

for i in range(6) where i % 2 == 0:
    print(i)
# 0 2 4

8.6while, break y continue

while repite mientras su condición booleana se cumpla. break sale del bucle más cercano; continue salta a la siguiente iteración.

n = 0
while n < 6:
    n += 1
    if n == 2:
        continue
    if n > 4:
        break
    print(n)
# 1 3 4
9 · Cuando algo falla

Errores y limpieza

Blizzard trata el fallo como un valor que puede capturarse. Pides un fallo con fail, acotas el riesgo con try, recibes el fallo con catch y garantizas la limpieza con always. Como los fallos son valores, la recuperación es código normal y no necesita ninguna jerarquía de clases.

9.1Tres tipos de errores

  • Errores del analizador significan que el texto no pudo convertirse en un programa. Llevan archivo, línea, columna y un caret.
  • Diagnósticos del comprobador llegan de blizzard check y del editor: nombres indefinidos, variables sin usar, código inalcanzable, módulos desconocidos, desajustes de tipo. No se ejecuta nada.
  • Errores en tiempo de ejecución ocurren mientras el programa corre y llevan el archivo, la línea, la columna y — si no se capturan — un rastro de pila.

9.2fail y recuperación

fn require_name(user):
    if user?.name == nil:
        fail("name is required")
    return user.name

try:
    print(require_name({}))
catch err:
    print("caught:", err)
always:
    print("cleanup runs either way")

# caught: name is required
# cleanup runs either way

fail lanza su único argumento, sea lo que sea. catch err vincula ese argumento a err (también puedes escribir catch a secas). always se ejecuta después del éxito y después de un catch.

9.3with: limpieza garantizada

Cuando un valor lleva una función close (un diccionario con un miembro close, o un objeto nativo que la ofrece), with expr as name: la llama al terminar el bloque, tanto si termina bien como si falla. Así es como los recursos se mantienen ordenados.

fn open_resource():
    return {data: "hello resource", close: fn(): print("closed")}

with open_resource() as res:
    print(res.data)
# hello resource
# closed

9.4Ocultar y luego detenerse: exit

Los números nativos como valores de error funcionan igual que las cadenas:

try:
    fail(42)
catch n:
    print(n + 1)   # 43

exit(code) detiene el intérprete con un código de salida de proceso opcional (0 o 1 argumento).

9.5assert

assert verifica una creencia y falla ruidosamente cuando se rompe.

  • assert(cond) falla si cond no es veraz.
  • assert(a, b) falla a menos que a sea igual a b (igualdad profunda).
  • assert(cond, "message") falla con un mensaje personalizado.
assert(2 + 2 == 4, "addition")
assert([1, 2], [1, 2])     # la igualdad profunda pasa
# assert(1, 2)  ->  assertion failed: expected 1, received 2

La veracidad es la regla que usan assert, bool() y filter: nil, false, 0, 0.0, "", [] y {} son falsos; todo lo demás es verdadero. Recuerda que if y while siguen exigiendo booleanos reales.

10 · Espacios de nombres

Módulos e importaciones

El código se organiza en módulos: espacios de nombres cuyos miembros son valores normales a los que se llega con un punto. Este capítulo explica las dos puertas a un módulo — using para la biblioteca estándar e import para archivos de Blizzard — y las reglas de visibilidad que controlan pub y priv.

10.1using: la biblioteca estándar

using http
using fs
using json

Cada using carga un módulo estándar en un nombre con el nombre del módulo. La forma larga using blizzard.http se acepta, y se permite un alias:

10.2import: tus propios archivos

Las importaciones relativas se resuelven sustituyendo los puntos por barras y vinculando el último segmento (o tu alias):

print(fmt.title("blizzard"))

import ./math_utils
print(math_utils.max3(1, 5, 3))

Los directorios superiores también están disponibles: import ../shared.validators. Los ciclos de importación se detectan y se informan con import cycle detected en lugar de quedarse dando vueltas para siempre.

10.3Importaciones de módulos de proyecto

Dentro de un proyecto con un blizzard.toml, los módulos se importan por el nombre del paquete y el archivo:

import demo.math
print(math.twice(21))

La dependencia dep.demo = "packages/demo" en blizzard.toml apunta a la ubicación del paquete (ver el capítulo 14).

10.4pub y priv

Todo lo que está en el nivel superior de un archivo es público por defecto. priv oculta un nombre de las exportaciones del archivo; pub hace explícita la intención. Un prefijo _ no oculta nada — solo priv lo hace.

# lib/values.blizz
pub fn max3(a, b, c):
    return max(a, b, c)

priv fn helper(x):
    return x * 2

pub top_value = 7
# main.blizz
import ./lib/values as v
print(v.max3(1, 5, 3))   # 5
# v.helper(2)  ->  attribute not found: helper

10.5Qué exporta un archivo importado

La exportación de un archivo es su entorno de nivel superior menos los nombres de las funciones incorporadas y menos los nombres priv. Los módulos se guardan en caché, así que importar el mismo archivo dos veces comparte una única copia.

16.1El programa completo

Si se pasó la palabra serve, el servidor se bloquea en api.serve(8080); si no, el puerto solo se registra y el programa termina. Una única fuente de verdad — el diccionario — conecta el almacenamiento, las rutas, el análisis de argumentos y las respuestas.

18 · Texto y números

Números, cadenas y texto

Los números y las cadenas son la materia prima de casi cualquier programa. Los capítulos 4 y 5 los recorrieron por encima; este capítulo es la referencia completa: las formas literales exactas, las reglas estrictas de conversión, la división en coma flotante, la indexación y las rebanadas que cuentan caracteres, la caja de herramientas de cadenas, los escapes y los f-strings aplicados.

18.1Formas literales de enteros

Un literal de entero es decimal por defecto. Los prefijos 0b/0B (binario), 0o/0O (octal) y 0x/0X (hexadecimal) eligen otra base, con los dígitos hexadecimales sin distinguir mayúsculas. Un - inicial es una negación ordinaria, no parte del literal.

print(42)       # 42
print(0b1010)   # 10
print(0o17)     # 15
print(0x1F)     # 31
print(-7)       # -7

La conversión int() es decimal exclusivamente: analiza una cadena en base 10 tras recortar los espacios circundantes. int(" 42 ") es 42, pero int("0x1A") es un error porque los prefijos de base son una característica de los literales, no del análisis.

print(int("42"))     # 42
print(int(3.99))     # 3      (truncado hacia cero)
print(int(true))     # 1
print(int(false))    # 0
print(int(0x1f))     # 31     (desde un int, sin cambios)

18.2Las conversiones que usarás de verdad

flt() convierte números, booleanos y cadenas a flotantes; str() muestra cualquier valor exactamente como lo hace print. Juntas cubren la gran mayoría de conversiones en programas reales. No hay coerción implícita: las cadenas nunca se convierten en números en silencio, así que "4" + 1 es un error de tipos.

print(flt(2))        # 2.0
print(flt("3.14"))   # 3.14
print(flt(" 2.5 "))  # 2.5
print(str(3.14))     # 3.14
print(str(100))      # 100
print(str(true))     # true

18.3La división siempre es flotante

El matiz más repetido en Blizzard: / siempre produce un flotante, tanto para enteros como para flotantes. // redondea hacia el infinito negativo, % toma el signo del dividendo y ** es asociativo por la derecha.

print(1 / 2)         # 0.5
print(7 / 2)         # 3.5
print(7 // 2)        # 3
print(-7 // 2)       # -4   (suelo, no truncamiento)
print(-7 % 2)        # 1    (signo del dividendo)
print(2 ** 3 ** 2)   # 512  (de derecha a izquierda: 2 ** 9)

Repetibles: "ab" * 3 es ababab, [1, 2] * 2 es [1, 2, 1, 2]; y + concatena cadenas, añade listas y fusiona diccionarios. Enteros y flotantes se comparan de forma cruzada: 1 == 1.0 es true.

18.4Indexación por caracteres

Las cadenas son secuencias de caracteres Unicode. La indexación y len() cuentan caracteres, no bytes, por lo que el texto multibyte se comporta correctamente. Los índices negativos cuentan desde el final y los fuera de rango son un error en tiempo de ejecución.

word = "blizzard"
print(word[0])     # s
print(word[-1])    # w
print(len("héllo"))# 5    (cinco caracteres, no seis bytes)
print("héllo"[1])  # é    (un único carácter)
print("abc"[5])    # error: index 5 out of range for a string of length 3

18.5Rebanadas

Las rebanadas son semiabiertas, s[inicio:fin]: el inicio se incluye y el final no. Cada rebanada devuelve una cadena nueva (las cadenas son inmutables). Las formas abiertas [:n] y [n:] son la forma habitual de tomar un prefijo o un sufijo; los límites negativos cuentan desde el final.

s = "blizzard"
print(s[:4])    # blizzard
print(s[4:])    # flake
print(s[4:6])   # fl
print(s[-3:])   # ake

18.6La caja de herramientas de cadenas

Seis funciones del núcleo cubren la mayor parte del trabajo con texto. upper, lower y trim cambian la caja y recortan el espacio circundante; split(cadena, sep) devuelve una lista de trozos; join(lista, sep) fusiona una lista de cadenas; replace(s, viejo, nuevo) reemplaza todas las apariciones; y contains(sujeto, aguja) es exactamente aguja in sujeto. Todas devuelven un valor nuevo.

print(upper("Blizzard"))      # BLIZZARD
print(lower("Blizzard"))      # blizzard
print(trim("  hi  "))     # hi
print(split("a,b,c", ","))# [a, b, c]
print(join(["sno", "man"], ""))  # snoman
print(replace("aaa", "a", "b"))  # bbb
print(contains("blizzard", "now"))# true

Combinadas, convierten texto bruto en datos útiles:

line = "  alice;ada;grace  "
names = split(trim(line), ";")
clean = map(fn(n): upper(trim(n)), names)
print(join(clean, "-"))   # ALICE-ADA-GRACE

18.7Escapes y texto sin formato

Existen exactamente seis escapes. Cualquier otra secuencia con barra invertida es un error.

EscapeCarácter
\nnueva línea
\ttabulación
\rretorno de carro
\\barra invertida
\"comillas dobles
\'comillas simples
print("a\tb")          # a	b
print("line1\nline2")  # dos líneas
print("no \d escape")  # error: unknown escape sequence \d

Las cadenas entre comillas triples ocupan varias líneas, de modo que el texto multilínea puede normalizarse en un solo paso:

poem = """the quick
brown fox"""
print(replace(poem, "\n", " "))   # the quick brown fox

18.8F-strings, a fondo

Una f antes de la comilla de apertura interpola cada {expresión}. Las llaves se anidan contando la profundidad, por lo que un literal de diccionario dentro de la interpolación funciona; {{ y }} producen llaves literales. Combinada con comillas triples, f interpola a lo largo de varias líneas. La interpolación siempre muestra con semántica de str() — convierte tú mismo cuando necesites otra forma.

name = "ada"
score = 97
print(f"player {name} scored {score}")  # player ada scored 97
print(f"{{name}}")                       # {name}
print(f"{ {a: 1} }")                    # {a: 1}
print(f"""triple
line {1 + 1}""")                        # triple / line 2
19 · Estructuras de datos

Colecciones en profundidad

Las listas y los diccionarios son los caballos de batalla de los programas Blizzard. Este capítulo es la referencia completa de comportamiento: qué operaciones mutan, cuáles devuelven valores nuevos, cómo construir y seleccionar de las listas, cómo se comportan de verdad los diccionarios y cómo razonar sobre toda una colección con map, filter y fold.

19.1Las listas son contenedores mutables

Una lista puede contener cualquier mezcla de valores, y la asignación a un índice muta la lista en el sitio. En cambio, append y la concatenación devuelven listas nuevas, por lo que debes conservar el resultado si lo quieres.

items = [1, 2, 3]
items[0] = 99
print(items)             # [99, 2, 3]  (mutada en el sitio)

print(append(items, 4))  # [99, 2, 3, 4]  (una lista nueva)
print(items)             # [99, 2, 3]     (sin cambios)

print([1, 2] + [3])      # [1, 2, 3]
print([1, 2] * 2)        # [1, 2, 1, 2]

matrix = [[1, 2], [3, 4]]
print(matrix[0][1])      # 2
matrix[1][0] = 30
print(matrix)            # [[1, 2], [30, 4]]

19.2Construir listas con idioma

El patrón acumulador — empezar con [] y reasignar append — es la forma estándar de hacer crecer una lista. range genera secuencias de enteros, incluso con paso.

evens = []
for n in range(0, 10, 2):
    evens = append(evens, n)
print(evens)          # [0, 2, 4, 6, 8]

print(enumerate(["a", "b"]))  # [[0, a], [1, b]]
print(zip([1, 2], ["a", "b"]))# [[1, a], [2, b]]

19.3Seleccionar de las listas

first y last leen los extremos, take y drop cortan desde el frente, y las rebanadas seleccionan cualquier ventana contigua por índice o por índice negativo. sort y reverse devuelven listas nuevas.

nums = [10, 20, 30, 40]
print(first(nums))   # 10
print(last(nums))    # 40
print(take(nums, 2)) # [10, 20]
print(drop(nums, 2)) # [30, 40]
print(nums[:2])      # [10, 20]
print(nums[2:])      # [30, 40]
print(nums[-2:])     # [30, 40]
print(sort([3, 1, 2]))   # [1, 2, 3]
print(reverse(nums))     # [40, 30, 20, 10]

19.4Bucles con estructura

La iteración con dos nombres sobre una lista produce índice y valor directamente — esa es la forma idiomática de tener ambos. Sobre un diccionario produce clave y valor, en orden de inserción. Para desestructurar pares, itera un resultado de zip o enumerate y vincula con [primero, segundo] = par.

for index, value in ["a", "b"]:
    print(index, value)        # 0 a / 1 b

for key, value in {"x": 1, "y": 2}:
    print(key, value)          # x 1 / y 2

for pair in zip(["a", "b"], [1, 2]):
    [letter, number] = pair
    print(letter, number)      # a 1 / b 2

19.5Diccionarios a fondo

Un diccionario asocia claves de cadena con valores y recuerda el orden de inserción. Las claves pueden escribirse sin comillas en los literales; los valores se alcanzan con un punto o un corchete. Asignar a una clave nueva la crea. get(dict, key) devuelve nil para una clave ausente (solo dos argumentos, sin valor por defecto), has comprueba la presencia e in sobre un diccionario comprueba claves.

config = {port: 8080, host: "localhost"}
print(config.port)         # 8080
print(config["host"])      # localhost
config.debug = true        # añade una clave nueva
print(config)              # {port: 8080, host: localhost, debug: true}
print(keys(config))        # [port, host, debug]
print(values(config))      # [8080, localhost, true]
print(has(config, "port")) # true
print(get(config, "missing"))  # nil
print("port" in config)    # true

+ fusiona dos diccionarios en uno nuevo; el operando derecho gana en los choques, y ambas entradas quedan intactas. Usa ?. y ?[ para acceso seguro ante nil en estructuras anidadas.

base  = {a: 1, shared: "left"}
more  = {shared: "right", b: 2}
print(base + more)   # {a: 1, shared: right, b: 2}
print(base)          # {a: 1, shared: left}  (sin cambios)

user = {contact: {email: "ada@example.com"}}
print(user?.contact?.email)      # ada@example.com
print({}?.contact?.email)        # nil
print({}?["name"])               # nil
print({}["name"])                # error: key not found: name

Un diccionario de conteo es un clásico; combina la asignación por corchetes con get y el fallback solo-para-nil ??:

counts = {}
words = ["blizzard", "blizzard", "flake"]
for w in words:
    counts[w] = (get(counts, w) ?? 0) + 1
print(counts)        # {blizzard: 2, flake: 1}

19.6Razonar sobre toda la colección

sum totaliza números, len cuenta elementos, any/all comprimen una lista de booleanos y map/filter/fold transforman, conservan y reducen. Componen con fluidez porque cada uno devuelve un valor.

grades = [90, 70, 85]
print(sum(grades))             # 245
print(len(grades))             # 3
print(sum(grades) / len(grades))  # 81.66666666666667
print(any([false, true]))      # true
print(all([true, true]))       # true
print(filter(fn(g): g >= 80, grades))  # [90, 85]
print(map(fn(g): g + 5, grades))       # [95, 75, 90]
print(fold(grades, 0, fn(total, g): total + g))  # 245

19.7Igualdad y pertenencia

== es igualdad estructural profunda: dos listas son iguales cuando tienen los mismos elementos en el mismo orden, y dos diccionarios cuando guardan las mismas claves asignadas a valores iguales. in es pertenencia profunda para listas, subcadena para cadenas y clave para diccionarios; not in la niega.

print([1, 2, 3] == [1, 2, 3])   # true
print([1, 2] == [2, 1])          # false
print({a: 1} == {a: 1})          # true
print(2 in [1, 2, 3])            # true
print([1, 2] in [[1, 2], [3]])   # true
print("ow" in "blizzard")            # true
print("b" in {a: 1, b: 2})       # true
print(3 not in [1, 2])           # true
20 · Funciones como valores

Funciones y closures en la práctica

Las funciones son valores de primera clase: se pueden guardar, pasar, devolver, invocar a través de una referencia y cerrar sobre su entorno. Este capítulo es el manual práctico — los patrones que usas a diario, cada uno con un ejemplo verificable.

20.1Las funciones son valores

Guarda una función en una variable, en una lista o en un diccionario, y llámala a través de ese valor. Un diccionario de manejadores es un interruptor limpio sin match.

handlers = {
    twice: fn(x): x * 2,
    half:  fn(x): x / 2,
}
print(handlers.twice(21))    # 42
print(handlers.half(21))     # 10.5
print(call(handlers.half, 21))  # 10.5

call(fn, args…) invoca una función guardada en un valor — lo mismo que escribir paréntesis.

20.2Parámetros y anotaciones de tipo

Los tipos en los parámetros y en el valor de retorno son opcionales y se comprueban en tiempo de ejecución, a la entrada y a la salida. Una discrepancia falla de forma sonora con el nombre y los tipos en juego, en lugar de fallar más abajo en la cadena.

fn add(left: int, right: int) -> int:
    return left + right

print(add(2, 3))      # 5
# add("x", 3)         ->  error de ejecución: discrepancia de tipos en left

20.3Los closures capturan su entorno

Una función captura los nombres visibles en el punto donde se crea y los conserva durante toda su vida. Una fábrica es el uso clásico: una función que construye funciones a medida.

fn make_adder(n):
    return fn(x): x + n

inc = make_adder(1)
print(inc(41))        # 42

minimum = 10
is_large = fn(value): value >= minimum
print(is_large(5))    # false
print(is_large(50))   # true

20.4Varios valores de retorno

return puede devolver varios valores, y la asignación por desestructuración los recibe todos a la vez. Los nombres no necesitan paréntesis a ningún lado.

fn split_point():
    return 10, 20

x, y = split_point()
print(x, y)    # 10 20

20.5Recursión

Las funciones pueden llamarse a sí mismas. La profundidad de recursión está protegida: el intérprete detiene la recursión desbocada con recursion limit exceeded en lugar de tumbar el sistema.

fn fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(10))    # 55

20.6Composición de orden superior

map, filter y fold reciben funciones como argumentos, de modo que una tubería es solo llamadas anidadas de izquierda a derecha. fold acepta el acumulador antes o después de la función: tanto fold(lista, acc, fn) como fold(fn, acc, lista) funcionan.

fn double(n):
    return n * 2
fn is_even(n):
    return n % 2 == 0
fn add(a, b):
    return a + b

numbers = [1, 2, 3, 4]
print(map(double, numbers))      # [2, 4, 6, 8]
print(filter(is_even, numbers))  # [2, 4]
print(fold(numbers, 0, add))     # 10
print(fold(add, 0, numbers))     # 10

Las funciones anónimas mantienen la composición en una línea:

names = ["ada", "linus", "grace"]
shouts = map(fn(n): upper(n), names)
print(shouts)    # [ADA, LINUS, GRACE]
21 · Endurecimiento

Errores, pruebas y defensa en profundidad

Un lenguaje pequeño sigue siendo honesto haciendo visible el fallo. Este capítulo convierte el capítulo 9 en una caja de herramientas: el contrato de fallos, la limpieza garantizada, escribir pruebas que blizzard test encuentre y los combinadores defensivos que mantienen a salvo los datos con forma de diccionario.

21.1El contrato de fallos

Existen tres clases de errores: los errores del analizador rechazan el texto que no puede convertirse en programa; los diagnósticos del comprobador vienen de blizzard check y del editor sin ejecutar nada; los errores de ejecución ocurren mientras el programa corre y llevan traza de pila. fail(x) lanza su único argumento — cualquier valor — y try/catch recibe exactamente ese valor.

fn require_name(user):
    if user?.name == nil:
        fail("name is required")
    return user.name

try:
    print(require_name({}))
catch err:
    print("caught:", err)
always:
    print("cleanup runs either way")

# caught: name is required
# cleanup runs either way

21.2Los fallos son valores

Como se puede lanzar cualquier valor, el equivalente a un código de error es simplemente un número que puedes comparar:

try:
    fail(42)
catch n:
    print(n + 1)   # 43

21.3always: limpieza que se ejecuta

always se ejecuta después de un cuerpo con éxito y después de un catch, de modo que cerrar un archivo o vaciar un mensaje no puede omitirse. with es la forma más corta cuando el propio valor sabe limpiarse: un diccionario u objeto nativo con un miembro close se cierra al terminar el bloque, normal o por fallo.

with {data: "hello resource", close: fn(): print("closed")} as res:
    print(res.data)
# hello resource
# closed

21.4assert en las pruebas

assert verifica una creencia y falla con estrépito cuando se rompe. blizzard test descubre todos los archivos *_test.blizz bajo src/; un archivo lleno de pequeñas llamadas a assert es una prueba. --filter restringe qué pruebas corren.

assert(2 + 2 == 4, "addition")
assert([1, 2], [1, 2])     # la igualdad profunda pasa
assert(has({a: 1}, "a"), "key present")

Las tres formas válidas: assert(cond) falla a menos que cond sea veraz; assert(a, b) falla a menos que a iguale a b por igualdad profunda; assert(cond, "mensaje") añade un mensaje.

21.5Defensa en profundidad

Los datos con forma de diccionario merecen lectores defensivos. Llega a las estructuras anidadas sin arriesgar un error de key not found, y falla rápido con una guarda de type() con nombre cuando la forma debe ser exacta.

print({}?.contact?.email)          # nil
print({}?["name"])                 # nil
print(get({port: 8080}, "port"))   # 8080
print(get({}, "port"))             # nil
print(has({}, "port"))             # false

fn respond(data):
    if type(data) != "dict":
        fail("respond expects a dictionary")
    return data?.message ?? "no message"

print(respond({message: "hi"}))    # hi
print(respond({}))                 # no message

?? es solo-para-nil: sustituye el lado derecho únicamente cuando el izquierdo es nil, nunca para false o 0. Recuerda que if y while necesitan booleanos de verdad — pero assert, bool() y filter usan veracidad.

22 · Proyectos reales

Módulos y proyectos en la práctica

Los capítulos 10 y 14 documentaron la maquinaria; este capítulo muestra la forma de trabajo de un proyecto real de varios archivos Blizzard: importaciones relativas, el contrato de visibilidad, las importaciones de módulos de proyecto y el ciclo de vida del proyecto con blizzard.

22.1Una estructura realista

my_app/
  blizzard.toml
  blizzard.lock
  src/
    main.blizz
    helpers_test.blizz
  lib/
    values.blizz
  packages/

src/main.blizz es el punto de entrada que ejecuta blizzard run; *_test.blizz bajo src/ los descubre blizzard test; el código compartido vive en sus propios archivos; las dependencias aterrizan en packages/.

22.2Importaciones relativas

Las importaciones relativas se resuelven sustituyendo los puntos por barras y vinculando el último segmento (o tu alias). El prefijo ../ sale del directorio actual.

import ./formatters as fmt
print(fmt.title("blizzard"))

import ../lib.values as v
print(v.max3(1, 5, 3))    # 5
print(v.top_value)        # 7

22.3El contrato de visibilidad

Todo lo que está en el nivel superior de un archivo se exporta por defecto. priv oculta un nombre de las exportaciones del archivo; pub hace explícita la intención pública (un prefijo _ no hace nada). Los módulos importados se guardan en caché, por lo que importar el mismo archivo dos veces comparte una copia, y los ciclos de importación se detectan y se notifican.

# lib/values.blizz
pub fn max3(a, b, c):
    return max(a, b, c)

priv fn helper(x):
    return x * 2

pub top_value = 7
# main.blizz
import ../lib.values as v
print(v.max3(1, 5, 3))   # 5
# v.helper(2)  ->  attribute not found: helper

22.4Importaciones de módulos de proyecto

Dentro de un proyecto, el código reutilizable se importa por nombre de paquete y ruta de archivo con puntos, y using acepta la forma larga blizzard. con un alias:

import demo.math
print(math.twice(21))        # 42

using blizzard.http as web
print(web.get("https://example.com").status)

La dependencia dep.demo = "packages/demo" en blizzard.toml apunta a la ubicación del paquete. blizzard.lock registra la versión exacta, la fuente y el checksum SHA-256, por lo que blizzard install reproduce el mismo árbol en cualquier máquina.

22.5Las funciones incorporadas siempre están a la vista

Las 52 funciones incorporadas no necesitan using — forman parte de todo programa. Solo la biblioteca estándar y tus propios archivos se cargan por nombre:

using api     using http   using fs     using sys   using cli
using db      using json   using csv    using env   using time
using crypto  using task   using input

22.6El flujo diario

Escribe, comprueba, prueba, ejecuta — el bucle son cuatro comandos:

blizzard fmt -w src/main.blizz   # formatear
blizzard check src/main.blizz   # análisis estático
blizzard test                 # ejecutar *_test.blizz
blizzard run --env .env       # ejecutar con configuración

blizzard get, add, remove, list, info, update, search e index gestionan las dependencias (ver capítulo 13), y el registro oficial ofrece por ahora estos paquetes: arrays, collections, csvutil, dict, guards, ids, math, numbers, pagination, query, result, stats, strings, template, text, validate.

23 · La máquina

El sistema de cerca

Todo lo que está fuera del intérprete es un módulo. Este último vistazo a fondo recorre los módulos del sistema uno a uno con ejemplos reales y ejecutables: sys, fs, env, time, csv, db, crypto, task y cli.

23.1sys — procesos y datos del host

sh ejecuta a través del shell y devuelve un diccionario con stdout, stderr, ok y code; exec ejecuta un programa directamente con la misma forma. El entorno, el directorio de trabajo y los datos de la máquina son lecturas simples.

using sys

result = sys.sh("echo hello-blizzard")
print(trim(result.stdout), result.ok)   # hello-blizzard true
print(sys.pid > 0)                      # true
print(sys.platform)                     # linux (ejemplo)
print(sys.arch)                         # amd64 (ejemplo)

23.2fs — archivos y directorios

read, write (sobrescribe) y append cubren los archivos; exists, is_file e is_dir preguntan por rutas; mkdir crea directorios de forma recursiva; list nombra un directorio; stat describe una ruta; copy duplica un archivo.

using fs

f = "demo.txt"
fs.write(f, "line one\n")
print(trim(fs.read(f)))        # line one
fs.append(f, "line two\n")
print(trim(fs.read(f)))        # line one / line two
print(fs.is_file(f))           # true
fs.remove(f)
print(fs.exists(f))            # false

fs.mkdir("out")
print(fs.is_dir("out"))        # true
fs.write("out/a.txt", "x")
print("a.txt" in fs.list("out"))   # true

23.3env — configuración

set y get leen y escriben el entorno del proceso; las coerciones int, float y bool aceptan un valor por defecto para variables ausentes o vacías; has pregunta; all vuelca todo; load lee líneas CLAVE=VALOR de un archivo, tolerando prefijos export y comillas.

using env

env.set("BLIZZARD_DEMO", "42")
print(env.get("BLIZZARD_DEMO"))          # 42
print(env.int("BLIZZARD_DEMO"))          # 42
print(env.float("MISSING", 1.5))     # 1.5
print(env.bool("MISSING", true))     # true
print(env.has("BLIZZARD_DEMO"))          # true
env.load(".env")                     # líneas CLAVE=VALOR

23.4time — relojes y duraciones

sleep acepta duraciones en cadena como "20ms" o un número de milisegundos; now usa por defecto 2006-01-02 15:04:05 y acepta directivas %; unix, unix_ms e iso son formatos listos; since(anterior) mide un intervalo.

using time

t0 = time.unix_ms()
time.sleep("10ms")
print(time.unix_ms() >= t0)          # true
print(len(trim(time.now())) == 19)   # true  (p. ej. 2026-09-19 12:00:00)
print(len(time.now("%Y-%m-%d")) == 10)  # true
print(len(time.iso()) > 10)           # true

23.5csv — tablas de texto

parse convierte texto en filas, dicts clavea las filas por la cabecera (dado el texto bruto), stringify serializa filas o diccionarios, y read/write trasladan filas de y hacia archivos.

using csv
using fs

raw = "name,score\nanna,95\nalex,88"
print(len(csv.parse(raw)))             # 3
print(csv.dicts(raw)[0].name)          # anna

rows = [["name", "score"], ["anna", "95"], ["alex", "88"]]
csv.write("out.csv", rows)
print(csv.read("out.csv")[1][1])       # 95
print(csv.dicts(fs.read("out.csv"))[0].name)  # anna

23.6db — un almacén de documentos JSON

db.open(ruta) carga un almacén clave-valor JSON (creando el archivo si no existe) y devuelve un objeto store. Ofrece get(clave, por_defecto?) — fíjate: el get de este store sí acepta un valor por defecto, a diferencia del get() incorporado — además de set, delete, keys, has, all, save y un miembro path.

using db

store = db.open("notes.json")
store.set("greeting", "hello")
store.set("count", 3)
print(store.get("greeting"))           # hello
print(store.get("missing", "default")) # default
print(store.has("count"))              # true
print(store.keys())                    # [greeting, count]
print(store.all())                     # {greeting: hello, count: 3}
store.save()                           # escritura atómica en disco

23.7crypto — hashes y tokens

sha256, sha1 y md5 devuelven hexadecimal en minúsculas; random_token(n?) devuelve n caracteres hexadecimales (32 por defecto); jwt_sign(payload, secreto) y jwt_verify(token, secreto) implementan tokens firmados, y verify devuelve nil cuando el secreto es incorrecto.

using crypto

print(len(crypto.sha256("hello")) == 64)   # true
print(len(crypto.random_token()) == 32)     # true
token = crypto.jwt_sign({role: "admin"}, "secret")
print(crypto.jwt_verify(token, "secret").role)  # admin
print(crypto.jwt_verify(token, "wrong") == nil) # true

Dos avisos que vale la pena repetir: los hashes no son cifrado, y los secretos viven en el entorno, no en los archivos fuente.

23.8task — trabajo programado y cli — argumentos y colores

task.every(duración, fn) ejecuta una función en un horario; task.after(ms, fn) la ejecuta una vez tras un retraso. Ambos devuelven un manejador con stop(). cli.parse(lista) divide los argumentos en {flags, args} con coerción de enteros y flotantes, y los ayudantes de color envuelven el texto en códigos ANSI (desactivados cuando hay tubería).

using task
using time
using cli

count = 0
fn bump():
    count = count + 1

job = task.every("5ms", bump)
time.sleep("30ms")
job.stop()
print(count >= 2)                  # true

parsed = cli.parse(["serve", "--port", "8080"])
print(parsed.args)       # [serve]
print(parsed.flags.port) # 8080
print(cli.green("ok"))   # texto en color (o plano con tubería)
