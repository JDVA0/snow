Foreword

Why a Small Language

Snow exists to build useful programs with less ceremony. It is a small, interpreted language: booleans, numbers, strings, lists, dictionaries, functions, and modules are nearly everything it has, and almost all of the outside world is reached through a module you load with using.

This book explains the whole language, completely and explicitly. Every value, every operator, every built-in function, every module, and every tool is described with its exact behavior and at least one verifiable example. Where a rule is subtle — division that always returns a float, a nil-only fallback, conditions that must be actual booleans — it is said out loud instead of left to intuition.

The best way to read it is with the interpreter open. Every listing in this book was designed to run. Type it, run it, change it, break it, and read what the error says: Snow’s errors point at the exact line, column, and offending construct.

1 · Getting Oriented

Start Here

A Snow program is a text file read from top to bottom. Statements assign values, call functions, import modules, define functions, or control execution. Blocks begin after a colon and use four spaces of indentation; there are no braces and no end keywords, so the shape of the file is the shape of the program.

1.1Your first program

Save this file as hello.snow:

Run it with the snowman command:

snowman hello.snow

print writes its arguments to the terminal, separated by single spaces, followed by a newline. The second line assigns the string "snow" to the name name. The third line concatenates two strings with + and prints Running: snow.

1.2Experimenting in the REPL

The REPL reads one statement at a time, evaluates it, and prints the result.

snowman repl

Inside it you see the prompt snow>. Type 2 + 2, press Enter, and it answers 4 with a yellow tint. A block header, like the one below, keeps the prompt open until you finish the block with a blank line; the indentation is added for you.

snow> pub fn cal(a, b):
...>     for i in range(a, b):
...>         print(i * 2)
...>
0
2

The empty line closes the block and the function body runs. For a quick experiment without saving a file, you can also evaluate a string directly:

snowman eval 'print("hi")'
snowman -e 'print(6 * 7)'

1.3Reading errors

Errors are precise. A parse error shows the file, line, column, and a caret under the offending character:

examples/test.snow:2:1: error: expected an indented block after the 'fn' statement
    fn add(a, b):
    ^

The message names the file, the line and column after the line number, tells you exactly what the parser expected, and prints the offending source line with a caret at the error position. Runtime errors carry the file, line, column, and — for uncaught failures — a stack trace.

1.4Project layout in one glance

For anything bigger than a scratch file, follow the convention: source in src/, tests in files whose name ends in _test.snow, and configuration in snow.toml. Run a whole project with snowman run, which picks src/main.snow automatically.

snowman init my_app
cd my_app
snowman run

Each piece is explained in depth in Chapter 14.

2 · Design

The Language Model

Snow follows a short execution pipeline: tokenize, parse, check, compile, interpret. Each stage has exactly one job, and each failure carries a precise location. Understanding this pipeline will help you interpret the errors you see.

  • Tokenizer. Turns source text into tokens. Indentation, numbers, strings, f-strings, and operators are its responsibility.
  • Parser. Builds a program tree. Its errors mean the source could not become a program at all — these are the most common beginner errors.
  • Checker. Inspects names, types, modules, and unreachable code without running the program. This is the static analysis behind snowman check and the editor diagnostics.
  • Compiler. Emits operations for a virtual machine.
  • Interpreter. Executes the operations. Runtime failures are reported with source location, and uncaught failures carry a stack trace.

2.1Dynamic by default

Names do not need annotations. The same variable can hold an integer, then later a string. Types are not optional decorations of a fixed contract: they are gradual. You may add annotations at the boundaries where a contract is valuable, and Snow checks them at runtime.

value = 10
value = "now a string"

2.2Values over classes

There are no classes. Lists, dictionaries, functions, modules, and native values compose directly, and data is always visible: a dictionary is the record, a list is the sequence, a function is the behavior.

2.3Explicit effects

Network, files, processes, and environment access live in modules (http, fs, sys). A program that touches the outside world has to say so. This keeps side effects visible and makes scripts predictable.

2.4Static analysis without running

Because the checker never executes the code, snowman check file.snow reports undefined names, unused variables, unreachable code, unknown modules, and type mismatches instantly and safely — no network calls, no file changes.

3 · The Write-Up

Source Text

This chapter covers the raw material of a Snow program: comments, names, keywords, indentation, numbers, and the three ways to write a string.

3.1Comments

A comment starts with # and runs to the end of the line. Comments are ignored by the interpreter and may appear after code.

# a whole-line comment
count = 1  # a trailing comment

3.2Names and keywords

Names contain letters, digits, and underscores, and may not begin with a digit. Unicode letters in names are allowed. Names are case-sensitive: count and Count are different variables.

The following words are reserved and cannot be used as names:

using import pub priv const as
fn return if elif else for in where while break continue
and or not try catch always match case with

That is the complete keyword list. true, false, and nil are values, not keywords.

3.3Indentation and layout

Blocks begin after a colon and use four spaces of indentation. Lines at the same indent are one block; a change of indentation opens or closes blocks. An indented block may also appear on the same line after the colon.

fn double(x): x * 2
if ready: print("go")

A semicolon can separate statements on one line:

a = 1; b = 2; print(a + b)

Long expressions can continue inside ( ), [ ], { }, and ?[ without a continuation character.

3.4Numbers

Integers may be written in decimal or in another base. Floats carry a decimal point and may end in one.

decimal     = 42
binary      = 0b1010
octal       = 0o17
hexadecimal = 0xFF
float_value = 3.14
trailing    = 9.

Bases also accept uppercase prefixes (0X, 0B, 0O). A digit invalid for the base is an error, so 0b102 and 0o8 fail to parse.

3.5Strings

Double and single quotes are equivalent. The only escapes are \n (newline), \t (tab), \r (carriage return), \\ (backslash), \", and \'. Any other backslash sequence is an error.

a = "double"
b = 'single'
c = "line one\ntab\there"

3.6Triple-quoted strings

Triple-quoted strings may span multiple lines and keep their line breaks.

poem = """
On the snow
a single line
of code.
"""

3.7F-strings

An f before the opening quote makes an f-string: {expression} inside it is evaluated and its result inserted. Braces are nested with depth counting, so f"{ {a: 1} }" works. Use {{ and }} for literal braces. Combine f with triple quotes for multiline interpolation.

user = "Ada"
age = 36
print(f"Hello, {user}!")
print(f"{user} is {age} years old.")
print(f"Curly: {{ {user} }}")

The output is Hello, Ada!, then Ada is 36 years old., then Curly: { Ada }. F-strings work with doubles, singles, and triple quotes (f"…", f'…', f"""…""").

4 · The Nouns

Values

Everything in Snow is a value. There are ten kinds: nil, booleans, integers, floats, strings, lists, dictionaries, functions, modules, and native values. This chapter defines each one precisely.

4.1nil

nil represents absence. It is not an error by itself: functions may return it, and the nullish operators treat it specially. An unset environment variable, a missing dictionary key under safe access, and an empty-result first all produce nil.

4.2Booleans, integers, floats

on = true
off = false
n = 42
p = 3.14159

Integers are arbitrary-width whole numbers. Floats are IEEE-754 doubles. An integer and a float compare equal when their value is the same: 1 == 1.0 is true.

4.3Strings

Strings are sequences of characters, indexed by character, not byte. Negative indices count from the end. Slicing uses half-open ranges [start:end] and is rune-aware.

s = "hello"
print(s[1])      # e
print(s[-1])     # o
print(s[1:4])    # ell
print(len(s))    # 5

The string methods familiar from other languages are plain functions here, so use upper(s), lower(s), and trim(s), not s.upper().

4.4Lists

Lists hold any values in order. They are mutable: you can assign through an index. Indexing supports negatives and slices just like strings.

items = [10, 20, 30]
print(items[0])   # 10
print(items[-1])  # 30
print(items[1:])  # [20, 30]
items[1] = 99     # mutate in place
print(items)      # [10, 99, 30]

A list can hold mixed types and other lists:

mix = [1, "two", [3, 4], {"five": 5}]

4.5Dictionaries

A dictionary maps keys to values and remembers insertion order. Keys may be written unquoted in literals. Access an attribute with a dot, a key with brackets, assign new keys freely, and iterate in insertion order.

config = {"theme": "dark"}
config.timeout = 30
config["region"] = "us"
print(config)             # {theme: dark, timeout: 30, region: us}
print(config.theme)       # dark
print(config["timeout"])  # 30

Reading a missing key with normal access is an error: config.nope raises key not found: nope. To read optional data safely use the nullish and safe-access operators from Chapter 5, or get(config, "nope"), which returns nil.

4.6Functions, modules, native values

Functions are values you define with fn or write as lambdas (Chapter 7). Modules are namespaces returned by using and import (Chapter 10). Native values are objects the host provides, such as the store returned by db.open (Chapter 12) and HTTP responses.

4.7Knowing the type

type(x) returns the kind of a value as a string. The possible names are: nil, bool, int, float, str, list, dict, fn, module, native, and response.

print(type(42))       # int
print(type([1, 2]))   # list
print(type({}))       # dict
print(type(nil))      # nil

4.8How values print

print renders values directly. Lists print as [a, b], dictionaries as {key: value}, and string contents inside collections print without quotes.

print(["a", "b"])              # [a, b]
print(keys({a: 1}))            # [a]
print({"name": "snow", "n": 2})# {name: snow, n: 2}

Floats print in the shortest form that preserves value: 3.5, 0.2, 2.5.

5 · The Verbs

Operators

Operators combine values into expressions. Snow uses words for logic (and, or, not, in) and symbols for arithmetic, comparison, and nullish handling. This chapter is the precise specification.

5.1Precedence, loosest first

5.2Arithmetic

print(7 + 2)   # 9
print(7 - 2)   # 5
print(7 * 2)   # 14
print(7 / 2)   # 3.5   (never integer division)
print(7 // 2)  # 3     (floor division)
print(7 % 2)   # 1

Division with / always returns a float: 7 / 2 is 3.5, not 3. Use // for floor division. The modulo operator % takes the sign of the dividend: -7 % 2 is 1, and -7 // 2 is -4 (floor, not truncation).

The power operator is right-associative and never a surprise:

print(2 ** 10)    # 1024
print(2 ** 3 ** 2)# 512   (2 ** (3 ** 2))
print(2 ** 0.5)   # 1.4142135623730951

+ concatenates strings, appends lists, and merges dictionaries; * repeats strings by a non-negative count.

print("snow" + "fall")   # snowfall
print("ab" * 3)          # ababab
print([1, 2] + [3])      # [1, 2, 3]

5.3Comparisons

Comparisons work on numbers (integers and floats are mutually comparable), strings (lexicographic), and booleans (false is less than true). Chains evaluate as read:

print(1 < 2 and 2 < 3)   # true
print(3 >= 3)             # true
print("abc" < "abd")      # true

Equality is deep: lists and dictionaries compare value by value. Mixing incomparable kinds raises an error: use type() to check first when in doubt.

5.4Logic and membership

print(true and false)     # false
print(not false)          # true
print("ow" in "snow")     # true  (substring)
print(3 in [1, 2, 3])     # true  (list membership)
print("x" not in {a: 1})  # true  (dict key test)
print(false or 2 == 2)    # true

and and or short-circuit: the second operand runs only if needed. They also require both operands to be booleans. in and not in are comparison operators: substring on strings, deep membership on lists, key test on dictionaries and modules.

5.5Nullish: ?? and ??=

?? returns its right side only when the left side is nil. Zero and false pass through untouched. ??= assigns the right side only if the left side is nil.

x = nil
print(x ?? "fallback")    # fallback
print(0 ?? "nope")        # 0
print(false ?? "nope")    # false
x ??= "assigned"
print(x)                  # assigned

5.6Safe access: ?. and ?[

Normal access raises on a missing key or an out-of-range index. Safe access returns nil instead, and a chain stops at the first absent value:

user = {name: "ada"}
print(user?.name)     # ada
print(user?.age)      # nil
print(user?.a?.b)     # nil   (chain stops early)
items = [1, 2, 3]
print(items?[9])      # nil
print(items?[1])      # 2

The nullish and safe access operators work together naturally for optional data: user?.email ?? "no email".

5.7The ternary

The conditional expression reads value if condition else other. Only the chosen branch is evaluated.

active = true
status = "on" if active else "off"
print(status)          # on

5.8Compound assignment

The augmented assignment operators += -= *= /= //= %= ??= apply the operator and store the result back on a single name.

n = 100
n += 20     # 120
n *= 2      # 240
n //= 7     # 34
print(n)    # 34
6 · Giving Meaning to Names

Assignments and Destructuring

Assignment binds a value to a name. Snow offers plain assignment, multiple assignment, typed assignment, constants, destructuring, and attribute or index assignment. Each has a specific shape.

6.1Assigning one value

count = 1
name = "snow"

6.2Assigning several names at once

Write several names on the left and the same number of values on the right:

a, b = 1, 2
print(a, b)      # 1 2

apple, banana = banana, apple   # swaps in one step

6.3Typed assignment

A name may carry a type that Snow checks at runtime: name: type = value. Supported types are int, float, str, bool, dict, list, nil, any, unions like int|float, and typed lists like str[].

age: int = 30
names: str[] = ["Ada", "Linus"]
either: int|float = 1.5

age = "thirty"           # runtime error: expected int, received str

A typed list checks every element at runtime:

nombres: str[] = ["Julian", "Ana"]
nombres = ["Julian", 5]  # error: element 1: expected str, received int

6.4Constants

const marks a name immutable. Reassigning it raises a runtime error.

const PORT = 8080
PORT = 9000    # error: const cannot be reassigned

6.5Destructuring lists

Unpack a single value into several names with bracket patterns:

[first, second] = [10, 20]
print(first, second)      # 10 20

head, rest = [1, 2, 3]    # the pattern matches what is given
print(head)               # 1
print(rest)               # 2  (rest is the second element)

A trailing comma or extra names handle the tail:

[a, b, c] = [1, 2, 3, 4]  # ignores the rest
print(a + b + c)            # 6

6.6Destructuring dictionaries

Braces pull named keys out of a dictionary:

point = {x: 10, y: 20}
{x, y} = point
print(x, y)      # 10 20

6.7Assigning through attributes and indexes

You can place a value through a dictionary key or a list index.

config = {}
config.theme = "dark"
config["timeout"] = 30

values = [1, 2, 3]
values[0] = 99
values[-1] = 33
print(values)      # [99, 2, 33]
print(config)      # {theme: dark, timeout: 30}

Dictionary keys must be strings; list indexes must be integers, and negatives count from the end.

7 · Building Blocks

Functions

Functions are values. You can define a named function, write an anonymous function expression, store functions in lists and dictionaries, pass them to higher-order helpers, and let them close over the names around them.

7.1Named functions

A fn block binds a name. Without a return, the function returns nil.

fn greet(name):
    return "Hello, " + name

print(greet("Ada"))    # Hello, Ada

7.2Parameters and return annotations

Types are optional and checked at runtime, on the arguments in and the value out:

fn repeat(word: str, times: int) -> str:
    return word * times

fn add(left: int, right: int) -> int:
    return left + right

print(add(2, 3))       # 5
print(repeat("ab", 3)) # ababab

A mismatch like add("x", 3) fails at runtime with the offending name and types. Untyped parameters stay dynamic.

7.3Anonymous functions

double = fn(value): value * 2
print(double(21))      # 42

fn apply(f, x):
    return f(x)

print(apply(double, 21))   # 42

An anonymous function with a single expression can be written on one line after the colon. A long body uses a block.

7.4return and multiple values

return alone returns nil. A function may return several values.

fn split_point():
    return 10, 20

x, y = split_point()
print(x, y)    # 10 20

7.5Closures

A function captures the names around it at its creation point.

minimum = 10
is_large = fn(value): value >= minimum
print(is_large(5))    # false
print(is_large(50))   # true

7.6Recursion

fn fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(10))    # 55

Recursion depth is protected by a limit; deep infinite recursion stops with an error rather than crashing the host.

7.7Higher-order helpers

map transforms every element, filter keeps those where a predicate returns true, and fold reduces a list. For fold, the accumulator can come before or after the function: fold(list, acc, fn) or fold(fn, acc, list).

fn double(n): n * 2
fn is_even(n): n % 2 == 0
fn add(a, b): a + b

numbers = [1, 2, 3, 4]

print(map(double, numbers))    # [2, 4, 6, 8]
print(filter(is_even, numbers))# [2, 4]
print(fold(numbers, 0, add))   # 10
print(fold(add, 0, numbers))   # 10

Higher-order functions are also a natural fit for lambdas:

names = ["ada", "linus", "grace"]
shouts = map(fn(n): upper(n), names)
print(shouts)    # [ADA, LINUS, GRACE]

7.8Calling through a value

call(fn, args…) invokes a function held in a value.

fn add3(a, b, c): a + b + c
print(call(add3, 1, 2, 3))   # 6
8 · Choices and Loops

Control Flow

Control flow bends the order of execution. Snow selects among branches with if and match, repeats with for and while, and lets break and continue steer loops precisely. One rule is worth stating twice: conditions must be actual booleans — several operators insist on true or false, not truthy values.

8.1if, elif, else

score = 85

if score >= 90:
    grade = "A"
elif score >= 70:
    grade = "B"
else:
    grade = "C"

print(grade)    # B

Each branch is a block. The condition between if and the colon must evaluate to a boolean.

8.2match and case

match compares a value against cases from top to bottom and runs the first match. A case may list several values. The wildcard _ must be alone in its case and must be last.

command = "stop"

match command:
    case "start", "go":
        print("starting")
    case "stop":
        print("stopping")
    case _:
        print("unknown")

# prints: stopping

8.3for loops

One name iterates the elements: values of a list, keys of a dictionary, characters of a string (by Unicode character), or numbers of a range.

for x in [10, 20, 30]:
    print(x)

for key in {"a": 1}:
    print(key)        # a

for ch in "snow":
    print(ch)         # s n o w (each on its line)

for i in range(3):
    print(i)          # 0 1 2

range(start, stop, step) takes integers only. stop is exclusive; the step can be negative and can never be zero.

8.4Two-name iteration

Two names receive pairs: index and value for lists and strings, key and value for dictionaries. To reach the pairs produced by enumerate or zip, iterate them and destructure with [first, second] = pair.

for index, value in ["a", "b"]:
    print(index, value)
# 0 a
# 1 b

for key, value in {"x": 1}:
    print(key, value)
# x 1

for pair in enumerate(["a", "b"]):
    [i, v] = pair
    print(i, v)
# 0 a
# 1 b

8.5Filtering with where

where attached to a for skips elements that do not satisfy the condition before the body runs.

for i in range(6) where i % 2 == 0:
    print(i)
# 0 2 4

8.6while, break, continue

while repeats while its boolean condition holds. break exits the nearest loop; continue jumps to the next iteration.

n = 0
while n < 6:
    n += 1
    if n == 2:
        continue
    if n > 4:
        break
    print(n)
# 1 3 4
9 · When Things Fail

Errors and Cleanup

Snow treats a failure as a value that can be caught. You ask for a failure with fail, bound the risk with try, receive the failure with catch, and guarantee cleanup with always. Because failures are values, recovery is plain code and requires no class hierarchy.

9.1Three kinds of errors

  • Parser errors mean the text could not become a program. They carry file, line, column, and a caret.
  • Checker diagnostics come from snowman check and the editor: undefined names, unused variables, unreachable code, unknown modules, type mismatches. Nothing executes.
  • Runtime errors happen while the program runs and carry file, line, column, and — if uncaught — a stack trace.

9.2fail and recovery

fn require_name(user):
    if user?.name == nil:
        fail("name is required")
    return user.name

try:
    print(require_name({}))
catch err:
    print("caught:", err)
always:
    print("cleanup runs either way")

# caught: name is required
# cleanup runs either way

fail throws its single argument, anyway. catch err binds that argument to err (you may also write catch alone). always runs after success and after a catch.

9.3with: guaranteed cleanup

When a value carries a close function (a dictionary with a close member, or a native object that provides one), with expr as name: calls it when the block ends, whether normally or by failure. This is how resources stay tidy.

fn open_resource():
    return {data: "hello resource", close: fn(): print("closed")}

with open_resource() as res:
    print(res.data)
# hello resource
# closed

9.4Hide, then stop: exit

Native numbers as error values work the same as strings:

try:
    fail(42)
catch n:
    print(n + 1)   # 43

exit(code) stops the interpreter with an optional process exit code (0 or 1 argument).

9.5assert

assert verifies a belief and fails loudly when it breaks.

  • assert(cond) fails if cond is not truthy.
  • assert(a, b) fails unless a equals b (deep equality).
  • assert(cond, "message") fails with a custom message.
assert(2 + 2 == 4, "addition")
assert([1, 2], [1, 2])     # deep equality passes
# assert(1, 2)  ->  assertion failed: expected 1, received 2

Truthiness is the rule used by assert, bool(), and filter: nil, false, 0, 0.0, "", [], and {} are falsy; everything else is truthy. Remember that if and while still require actual booleans.

10 · Namespaces

Modules and Imports

Code is organized into modules: namespaces whose members are ordinary values reached with a dot. This chapter explains both doors into a module — using for the standard library and import for Snow files — and the visibility rules controlled by pub and priv.

10.1using: the standard library

using http
using fs
using json

response = http.get("https://example.com")
print(response.status)

Each using loads one standard module into a name with the module’s name. The long form using snow.http is accepted, and an alias is allowed:

using snow.http as web
print(web.get("https://example.com").status)

10.2import: your own files

Relative imports resolve by replacing dots with slashes and binding the last segment (or your alias):

import ./formatters as fmt
print(fmt.title("snow"))

import ./math_utils
print(math_utils.max3(1, 5, 3))

Parent directories are available too: import ../shared.validators. Import cycles are detected and reported with import cycle detected instead of looping forever.

10.3Project-module imports

Inside a project with a snow.toml, modules are imported by their package name and file:

import demo.math
print(math.twice(21))

The dependency dep.demo = "packages/demo" in snow.toml points to the package’s location (see Chapter 14).

10.4pub and priv

Everything at the top level of a file is public by default. priv hides a name from the exports of the file; pub makes intent explicit. A _ prefix does not hide anything — only priv does.

# lib/values.snow
pub fn max3(a, b, c):
    return max(a, b, c)

priv fn helper(x):
    return x * 2

pub top_value = 7
# main.snow
import ./lib/values as v
print(v.max3(1, 5, 3))   # 5
# v.helper(2)  ->  attribute not found: helper

10.5What an imported file exports

The export of a file is its top-level environment minus built-in function names minus priv names. Modules are cached, so importing the same file twice shares one copy.

11 · Ready-Made Verbs

Built-in Functions

Snow ships 52 built-in functions, always available, no using needed. They fall into a handful of families: output and input, conversions, math, strings, collections, reasoning about collections, safety, and process control. Each is specified below with a verifiable example.

11.1Output and input

print("a", "b", 1)   # a b 1     (single spaces, one newline)
input("Name: ")      # reads a line, prints the prompt
  • print(…) — writes arguments separated by single spaces, then a newline.
  • input(prompt?) — prints an optional prompt, reads a line, strips the newline. Returns nil at end of input.

18 · Text and Numbers

Numbers, Strings, and Text

Numbers and strings are the raw material of nearly every program. Chapters 4 and 5 toured them; this chapter is the full reference: the exact literal forms, the strict conversion rules, float division, character-aware indexing and slicing, the string toolbox, escapes, and f-strings applied.

18.1Integer literal forms

An integer literal is decimal by default. The prefixes 0b/0B (binary), 0o/0O (octal), and 0x/0X (hexadecimal) select another base, with hexadecimal digits case-insensitive. A leading - is ordinary negation, not part of the literal.

print(42)       # 42
print(0b1010)   # 10
print(0o17)     # 15
print(0x1F)     # 31
print(-7)       # -7

The conversion function int() is decimal-only: it parses a string in base 10 after trimming surrounding whitespace. int(" 42 ") is 42, but int("0x1A") is an error because base prefixes are a literal feature, not a parsing one.

print(int("42"))     # 42
print(int(3.99))     # 3      (truncated toward zero)
print(int(true))     # 1
print(int(false))    # 0
print(int(0x1f))     # 31     (from an int, unchanged)

18.2Conversions you will actually use

flt() converts numbers, booleans, and strings to floats; str() renders any value exactly the way print does. Together they cover the overwhelming majority of conversions in real programs. There is no implicit coercion: strings are never silently turned into numbers, so "4" + 1 is a type error.

print(flt(2))        # 2.0
print(flt("3.14"))   # 3.14
print(flt(" 2.5 "))  # 2.5
print(str(3.14))     # 3.14
print(str(100))      # 100
print(str(true))     # true

18.3Division is always float

The single most repeated subtlety in Snow: / always produces a float, for integers and floats alike. // floors toward negative infinity, % takes the sign of the dividend, and ** is right-associative.

print(1 / 2)         # 0.5
print(7 / 2)         # 3.5
print(7 // 2)        # 3
print(-7 // 2)       # -4   (floor, not truncation)
print(-7 % 2)        # 1    (sign of the dividend)
print(2 ** 3 ** 2)   # 512  (right to left: 2 ** 9)

Repeatables: "ab" * 3 is ababab, [1, 2] * 2 is [1, 2, 1, 2], and + concatenates strings, appends lists, and merges dictionaries. Integers and floats compare equal across types: 1 == 1.0 is true.

18.4Character-aware indexing

Strings are sequences of Unicode characters. Indexing and len() count characters, not bytes, so multi-byte text behaves correctly. Negative indices count from the end, and out-of-range indexes are an error at runtime.

word = "snow"
print(word[0])     # s
print(word[-1])    # w
print(len("héllo"))# 5    (five characters, not six bytes)
print("héllo"[1])  # é    (a single character)
print("abc"[5])    # error: index 5 out of range for a string of length 3

18.5Slices

Slices are half-open, s[start:end]: the start is included, the end is not. Every slice returns a new string (strings are immutable). The open forms [:n] and [n:] are the usual way to take a prefix or a suffix; negative bounds count from the end.

s = "snowflake"
print(s[:4])    # snow
print(s[4:])    # flake
print(s[4:6])   # fl
print(s[-3:])   # ake

18.6The string toolbox

Six core functions cover most text work. upper, lower, and trim change case and strip surrounding whitespace; split(str, sep) yields a list of pieces; join(list, sep) fuses a list of strings; replace(s, old, new) replaces every occurrence; and contains(subject, needle) is exactly needle in subject. Every one returns a new value.

print(upper("Snow"))      # SNOW
print(lower("Snow"))      # snow
print(trim("  hi  "))     # hi
print(split("a,b,c", ","))# [a, b, c]
print(join(["sno", "man"], ""))  # snoman
print(replace("aaa", "a", "b"))  # bbb
print(contains("snowman", "now"))# true

Combined, they turn raw text into usable data:

line = "  alice;ada;grace  "
names = split(trim(line), ";")
clean = map(fn(n): upper(trim(n)), names)
print(join(clean, "-"))   # ALICE-ADA-GRACE

18.7Escapes and raw text

Exactly six escapes exist. Any other backslash sequence is an error.

EscapeCharacter
\nnewline
\ttab
\rcarriage return
\\backslash
\"double quote
\'single quote
print("a\tb")          # a	b
print("line1\nline2")  # two lines
print("no \d escape")  # error: unknown escape sequence \d

Triple-quoted strings span lines, so multi-line text can be normalized in one step:

poem = """the quick
brown fox"""
print(replace(poem, "\n", " "))   # the quick brown fox

18.8F-strings, fully

An f before the opening quote interpolates every {expression}. Braces nest with depth counting, so a dictionary literal inside the interpolation works; {{ and }} produce literal braces. Combined with triple quotes, f interpolates across lines. Interpolation always renders with str() semantics — convert yourself when you need a different shape.

name = "ada"
score = 97
print(f"player {name} scored {score}")  # player ada scored 97
print(f"{{name}}")                       # {name}
print(f"{ {a: 1} }")                    # {a: 1}
print(f"""triple
line {1 + 1}""")                        # triple / line 2
19 · Data Structures

Collections in Depth

Lists and dictionaries are the workhorses of Snow programs. This chapter is the full behavioral reference: which operations mutate, which return new values, how to build and select from lists, how dictionaries actually behave, and how to reason across a whole collection with map, filter, and fold.

19.1Lists are mutable containers

A list can hold any mix of values, and assignment to an index mutates the list in place. By contrast, append and concatenation return new lists, so you must keep the result if you want it.

items = [1, 2, 3]
items[0] = 99
print(items)             # [99, 2, 3]  (mutated in place)

print(append(items, 4))  # [99, 2, 3, 4]  (a new list)
print(items)             # [99, 2, 3]     (unchanged)

print([1, 2] + [3])      # [1, 2, 3]
print([1, 2] * 2)        # [1, 2, 1, 2]

matrix = [[1, 2], [3, 4]]
print(matrix[0][1])      # 2
matrix[1][0] = 30
print(matrix)            # [[1, 2], [30, 4]]

19.2Building lists idiomatically

The accumulator pattern — start with [] and reassign append — is the standard way to grow a list. range generates integer sequences, including with a step.

evens = []
for n in range(0, 10, 2):
    evens = append(evens, n)
print(evens)          # [0, 2, 4, 6, 8]

print(enumerate(["a", "b"]))  # [[0, a], [1, b]]
print(zip([1, 2], ["a", "b"]))# [[1, a], [2, b]]

19.3Selecting from lists

first and last read the ends, take and drop cut from the front, and slices select any contiguous window by index or by negative index. sort and reverse return new lists.

nums = [10, 20, 30, 40]
print(first(nums))   # 10
print(last(nums))    # 40
print(take(nums, 2)) # [10, 20]
print(drop(nums, 2)) # [30, 40]
print(nums[:2])      # [10, 20]
print(nums[2:])      # [30, 40]
print(nums[-2:])     # [30, 40]
print(sort([3, 1, 2]))   # [1, 2, 3]
print(reverse(nums))     # [40, 30, 20, 10]

19.4Looping with structure

Two-name iteration over a list yields index and value directly — that is the idiomatic way to get both. Over a dictionary it yields key and value, in insertion order. To destructure pairs, iterate a zip or enumerate result and bind with [first, second] = pair.

for index, value in ["a", "b"]:
    print(index, value)        # 0 a / 1 b

for key, value in {"x": 1, "y": 2}:
    print(key, value)          # x 1 / y 2

for pair in zip(["a", "b"], [1, 2]):
    [letter, number] = pair
    print(letter, number)      # a 1 / b 2

19.5Dictionaries in full

A dictionary maps string keys to values and remembers insertion order. Keys may be written unquoted in literals; values are reached with a dot or a bracket. Assigning to a new key creates it. get(dict, key) returns nil for a missing key (two arguments only, no default), has tests membership, and in on a dictionary tests keys.

config = {port: 8080, host: "localhost"}
print(config.port)         # 8080
print(config["host"])      # localhost
config.debug = true        # adds a new key
print(config)              # {port: 8080, host: localhost, debug: true}
print(keys(config))        # [port, host, debug]
print(values(config))      # [8080, localhost, true]
print(has(config, "port")) # true
print(get(config, "missing"))  # nil
print("port" in config)    # true

+ merges two dictionaries into a new one; the right operand wins on clashes, and both inputs stay untouched. Use ?. and ?[ for nil-safe access into nested structures.

base  = {a: 1, shared: "left"}
more  = {shared: "right", b: 2}
print(base + more)   # {a: 1, shared: right, b: 2}
print(base)          # {a: 1, shared: left}  (unchanged)

user = {contact: {email: "ada@example.com"}}
print(user?.contact?.email)      # ada@example.com
print({}?.contact?.email)        # nil
print({}?["name"])               # nil
print({}["name"])                # error: key not found: name

A counter dictionary is a classic; combine bracket assignment with get and the nil-only fallback ??:

counts = {}
words = ["snow", "snow", "flake"]
for w in words:
    counts[w] = (get(counts, w) ?? 0) + 1
print(counts)        # {snow: 2, flake: 1}

19.6Reasoning across a collection

sum totals numbers, len counts elements, any/all compress a list of booleans, and map/filter/fold transform, keep, and reduce. They compose fluently because each returns a value.

grades = [90, 70, 85]
print(sum(grades))             # 245
print(len(grades))             # 3
print(sum(grades) / len(grades))  # 81.66666666666667
print(any([false, true]))      # true
print(all([true, true]))       # true
print(filter(fn(g): g >= 80, grades))  # [90, 85]
print(map(fn(g): g + 5, grades))       # [95, 75, 90]
print(fold(grades, 0, fn(total, g): total + g))  # 245

19.7Equality and membership

== is deep structural equality: two lists are equal when they have the same elements in the same order, and two dictionaries when they hold the same keys mapped to equal values. in is deep membership for lists, substring for strings, and key membership for dictionaries; not in negates it.

print([1, 2, 3] == [1, 2, 3])   # true
print([1, 2] == [2, 1])          # false
print({a: 1} == {a: 1})          # true
print(2 in [1, 2, 3])            # true
print([1, 2] in [[1, 2], [3]])   # true
print("ow" in "snow")            # true
print("b" in {a: 1, b: 2})       # true
print(3 not in [1, 2])           # true
20 · Functions as Values

Functions and Closures in Practice

Functions are first-class values: they can be stored, passed, returned, called through a reference, and closed over. This chapter is the practical manual — the patterns you reach for every day, each one with a verifiable example.

20.1Functions are values

Store a function in a variable, in a list, or in a dictionary, then call it through that value. A dictionary of handlers is a clean switch without a match.

handlers = {
    twice: fn(x): x * 2,
    half:  fn(x): x / 2,
}
print(handlers.twice(21))    # 42
print(handlers.half(21))     # 10.5
print(call(handlers.half, 21))  # 10.5

call(fn, args…) invokes a function held in a value — the same as writing parentheses.

20.2Parameters and type annotations

Types on parameters and on the return value are optional and checked at runtime, on the way in and on the way out. A mismatch fails loudly with the offending name and types instead of failing somewhere downstream.

fn add(left: int, right: int) -> int:
    return left + right

print(add(2, 3))      # 5
# add("x", 3)         ->  runtime error: type mismatch on left

20.3Closures capture their surroundings

A function captures the names visible at its creation point, and it keeps them for its whole life. A factory is the classic use: a function that builds tailored functions.

fn make_adder(n):
    return fn(x): x + n

inc = make_adder(1)
print(inc(41))        # 42

minimum = 10
is_large = fn(value): value >= minimum
print(is_large(5))    # false
print(is_large(50))   # true

20.4Multiple return values

return can hand back several values, and destructuring assignment receives them all at once. The names do not need parentheses on either side.

fn split_point():
    return 10, 20

x, y = split_point()
print(x, y)    # 10 20

20.5Recursion

Functions may call themselves. Recursion depth is protected: the interpreter stops runaway recursion with recursion limit exceeded rather than crashing the host.

fn fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(10))    # 55

20.6Higher-order composition

map, filter, and fold take functions as arguments, so a pipeline is just nested calls left to right. fold accepts the accumulator before or after the function: both fold(list, acc, fn) and fold(fn, acc, list) work.

fn double(n):
    return n * 2
fn is_even(n):
    return n % 2 == 0
fn add(a, b):
    return a + b

numbers = [1, 2, 3, 4]
print(map(double, numbers))      # [2, 4, 6, 8]
print(filter(is_even, numbers))  # [2, 4]
print(fold(numbers, 0, add))     # 10
print(fold(add, 0, numbers))     # 10

Anonymous functions keep the composition inline:

names = ["ada", "linus", "grace"]
shouts = map(fn(n): upper(n), names)
print(shouts)    # [ADA, LINUS, GRACE]
21 · Hardening

Errors, Tests, and Defense in Depth

A small language stays honest by making failure visible. This chapter turns Chapter 9 into a toolkit: the failure contract, guaranteed cleanup, writing tests that snowman test will find, and the defensive combinators that keep dictionary-shaped data safe.

21.1The failure contract

Three kinds of errors exist: parser errors reject text that cannot become a program; checker diagnostics come from snowman check and the editor without running anything; runtime errors happen while the program runs and carry a stack trace. fail(x) throws its single argument — any value — and try/catch receives that exact value.

fn require_name(user):
    if user?.name == nil:
        fail("name is required")
    return user.name

try:
    print(require_name({}))
catch err:
    print("caught:", err)
always:
    print("cleanup runs either way")

# caught: name is required
# cleanup runs either way

21.2Failures are values

Because any value can be thrown, the equivalent of an error code is just a number you can compare:

try:
    fail(42)
catch n:
    print(n + 1)   # 43

21.3always: cleanup that runs

always runs after a successful body and after a catch, so closing a file or flushing a message cannot be skipped. with is the shorter form when the value itself knows how to clean up: a dictionary or native object with a close member is closed when the block ends, normally or by failure.

with {data: "hello resource", close: fn(): print("closed")} as res:
    print(res.data)
# hello resource
# closed

21.4assert in tests

assert verifies a belief and fails loudly when it breaks. snowman test discovers every *_test.snow file under src/; a file full of small assert calls is a test. --filter narrows which tests run.

assert(2 + 2 == 4, "addition")
assert([1, 2], [1, 2])     # deep equality passes
assert(has({a: 1}, "a"), "key present")

The three valid shapes: assert(cond) fails unless cond is truthy; assert(a, b) fails unless a equals b by deep equality; assert(cond, "message") adds a message.

21.5Defense in depth

Dictionary-shaped data deserves defensive readers. Reach into nested structure without risking a key not found error, and fail fast with a named type() guard when the shape must be exact.

print({}?.contact?.email)          # nil
print({}?["name"])                 # nil
print(get({port: 8080}, "port"))   # 8080
print(get({}, "port"))             # nil
print(has({}, "port"))             # false

fn respond(data):
    if type(data) != "dict":
        fail("respond expects a dictionary")
    return data?.message ?? "no message"

print(respond({message: "hi"}))    # hi
print(respond({}))                 # no message

?? is nil-only: it substitutes the right side only when the left side is nil, never for false or 0. Remember that if and while need real booleans — but assert, bool(), and filter use truthiness.

22 · Real Projects

Modules and Projects in Practice

Chapters 10 and 14 documented the machinery; this chapter shows the working shape of a real multi-file Snow project: relative imports, the visibility contract, project-module imports, and the project lifecycle with snowman.

22.1A realistic layout

my_app/
  snow.toml
  snow.lock
  src/
    main.snow
    helpers_test.snow
  lib/
    values.snow
  packages/

src/main.snow is the entry point that snowman run executes; *_test.snow under src/ are discovered by snowman test; shared code lives in its own files; dependencies land in packages/.

22.2Relative imports

Relative imports resolve by replacing dots with slashes and binding the last segment (or your alias). The ../ prefix crosses out of the current directory.

import ./formatters as fmt
print(fmt.title("snow"))

import ../lib.values as v
print(v.max3(1, 5, 3))    # 5
print(v.top_value)        # 7

22.3The visibility contract

Everything at the top level of a file exports by default. priv hides a name from the file’s exports; pub makes public intent explicit (a _ prefix does nothing). Imported modules are cached, so importing the same file twice shares one copy, and import cycles are detected and reported.

# lib/values.snow
pub fn max3(a, b, c):
    return max(a, b, c)

priv fn helper(x):
    return x * 2

pub top_value = 7
# main.snow
import ../lib.values as v
print(v.max3(1, 5, 3))   # 5
# v.helper(2)  ->  attribute not found: helper

22.4Project-module imports

Inside a project, reusable code is imported by package name and file path with dots, and using accepts the long snow. form with an alias:

import demo.math
print(math.twice(21))        # 42

using snow.http as web
print(web.get("https://example.com").status)

The dependency dep.demo = "packages/demo" in snow.toml points to the package’s location. snow.lock records the exact version, source, and SHA-256 checksum, so snowman install reproduces the same tree everywhere.

22.5The built-ins are always in scope

The 52 built-in functions need no using — they are part of every program. Only the standard library and your own files are loaded by name:

using api     using http   using fs     using sys   using cli
using db      using json   using csv    using env   using time
using crypto  using task   using input

22.6The daily workflow

Write, check, test, run — the loop is four commands:

snowman fmt -w src/main.snow   # format
snowman check src/main.snow   # static analysis
snowman test                 # run *_test.snow
snowman run --env .env       # run with configuration

snowman get, add, remove, list, info, update, search, and index manage dependencies (see Chapter 13), and the official registry currently offers these packages: arrays, collections, csvutil, dict, guards, ids, math, numbers, pagination, query, result, stats, strings, template, text, validate.

23 · The Machine

The System Close-Up

Everything outside the interpreter is a module. This final deep dive works through the system modules one by one with real, runnable examples: sys, fs, env, time, csv, db, crypto, task, and cli.

23.1sys — processes and host facts

sh runs through the shell and returns a dictionary with stdout, stderr, ok, and code; exec runs a program directly with the same shape. Environment, working directory, and machine facts are plain reads.

using sys

result = sys.sh("echo hello-snow")
print(trim(result.stdout), result.ok)   # hello-snow true
print(sys.pid > 0)                      # true
print(sys.platform)                     # linux (example)
print(sys.arch)                         # amd64 (example)

23.2fs — files and directories

read, write (overwrite), and append cover files; exists, is_file, and is_dir ask about paths; mkdir creates directories recursively; list names a directory; stat describes a path; copy duplicates a file.

using fs

f = "demo.txt"
fs.write(f, "line one\n")
print(trim(fs.read(f)))        # line one
fs.append(f, "line two\n")
print(trim(fs.read(f)))        # line one / line two
print(fs.is_file(f))           # true
fs.remove(f)
print(fs.exists(f))            # false

fs.mkdir("out")
print(fs.is_dir("out"))        # true
fs.write("out/a.txt", "x")
print("a.txt" in fs.list("out"))   # true

23.3env — configuration

set and get read and write the process environment; the int, float, and bool coercions accept a default for missing or empty variables; has asks; all dumps everything; load reads KEY=VALUE lines from a file, tolerating export prefixes and quotes.

using env

env.set("SNOW_DEMO", "42")
print(env.get("SNOW_DEMO"))          # 42
print(env.int("SNOW_DEMO"))          # 42
print(env.float("MISSING", 1.5))     # 1.5
print(env.bool("MISSING", true))     # true
print(env.has("SNOW_DEMO"))          # true
env.load(".env")                     # KEY=VALUE lines

23.4time — clocks and durations

sleep accepts string durations such as "20ms" or a plain millisecond number; now defaults to 2006-01-02 15:04:05 and accepts % directives; unix, unix_ms, and iso are ready-made formats; since(prev) measures an interval.

using time

t0 = time.unix_ms()
time.sleep("10ms")
print(time.unix_ms() >= t0)          # true
print(len(trim(time.now())) == 19)   # true  (e.g. 2026-09-19 12:00:00)
print(len(time.now("%Y-%m-%d")) == 10)  # true
print(len(time.iso()) > 10)           # true

23.5csv — tables of text

parse turns text into rows, dicts keys rows by the header (given the raw text), stringify serializes rows or dictionaries, and read/write move rows to and from files.

using csv
using fs

raw = "name,score\nanna,95\nalex,88"
print(len(csv.parse(raw)))             # 3
print(csv.dicts(raw)[0].name)          # anna

rows = [["name", "score"], ["anna", "95"], ["alex", "88"]]
csv.write("out.csv", rows)
print(csv.read("out.csv")[1][1])       # 95
print(csv.dicts(fs.read("out.csv"))[0].name)  # anna

23.6db — a JSON document store

db.open(path) loads a JSON key-value store (creating the file if absent) and returns a store object. It offers get(key, default?) — note this store’s get does take a default, unlike the built-in get() — plus set, delete, keys, has, all, save, and a path member.

using db

store = db.open("notes.json")
store.set("greeting", "hello")
store.set("count", 3)
print(store.get("greeting"))           # hello
print(store.get("missing", "default")) # default
print(store.has("count"))              # true
print(store.keys())                    # [greeting, count]
print(store.all())                     # {greeting: hello, count: 3}
store.save()                           # atomic write to disk

23.7crypto — hashes and tokens

sha256, sha1, and md5 return lowercase hex; random_token(n?) returns n hex characters (32 by default); jwt_sign(payload, secret) and jwt_verify(token, secret) implement signed tokens, with verify returning nil when the secret is wrong.

using crypto

print(len(crypto.sha256("hello")) == 64)   # true
print(len(crypto.random_token()) == 32)     # true
token = crypto.jwt_sign({role: "admin"}, "secret")
print(crypto.jwt_verify(token, "secret").role)  # admin
print(crypto.jwt_verify(token, "wrong") == nil) # true

Two warnings worth repeating: hashes are not encryption, and secrets belong in the environment, not in source files.

23.8task — scheduled work and cli — arguments and colors

task.every(duration, fn) runs a function on a schedule; task.after(ms, fn) runs it once after a delay. Both return a handle with stop(). cli.parse(list) splits arguments into {flags, args} with integer and float coercion, and the color helpers wrap text in ANSI codes (disabled when piped).

using task
using time
using cli

count = 0
fn bump():
    count = count + 1

job = task.every("5ms", bump)
time.sleep("30ms")
job.stop()
print(count >= 2)                  # true

parsed = cli.parse(["serve", "--port", "8080"])
print(parsed.args)       # [serve]
print(parsed.flags.port) # 8080
print(cli.green("ok"))   # colored text (or plain when piped)

The ask/confirm/box/table/divider/info/success/warn/error helpers complete the kit (see Chapter 12).
