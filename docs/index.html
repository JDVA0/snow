Snow language reference

Build useful programs with less ceremony.

Snow is a small interpreted language implemented in Go. It is designed for scripts, command-line tools, web APIs, and automation. This page is the complete guide: read it from the beginning to learn Snow, or use the contents as a reference.

Design idea. Snow keeps the syntax close to the data it manipulates. Indentation defines blocks, dictionaries represent structured records, modules expose ordinary values, and errors can be handled at clear boundaries.

01 · Start here

Install the command-line runner from the repository:

go build -o snowman ./cmd/snowman
./snowman hello.snow

Create hello.snow:

print("hello, Snow")

A Snow file is read from top to bottom. Statements can assign values, call functions, import modules, define functions, or control execution. Blocks begin after a colon and use four spaces.

name = "Ada"
if name == "Ada":
    print("welcome, " + name)

For experiments, use snowman repl. For a project, keep source in src/, tests in files ending with _test.snow, and configuration in snow.toml.

02 · Language model

Snow follows a simple execution pipeline. The tokenizer turns source text into tokens. The parser builds a program tree. The checker can inspect names, types, modules, and unreachable code without running the program. The compiler emits VM operations, and the interpreter executes them.

Dynamic by defaultNames do not need annotations. Add types at boundaries where a contract is valuable.
Values over classesLists, dictionaries, functions, modules, and native values are composed directly.
Explicit effectsNetwork, files, processes, and environment access live in modules.

Use snowman check file.snow to get feedback without executing network calls or changing files. Runtime errors include source location and, for uncaught failures, a stack trace.

03 · Syntax and values

Comments and names

A comment starts with #. Names contain letters, digits, and underscores, but cannot begin with a digit. Keywords are reserved.

# A comment explains intent.
server_name = "local"
server_name = server_name + "host"

Primitive values

Snow has nil, booleans, integers, floats, strings, lists, dictionaries, functions, modules, and native values.

missing = nil
enabled = true
count = 42
ratio = 4.5
message = "hello"

Lists and dictionaries

numbers = [1, 2, 3]
user = {name: "Ada", active: true}
print(numbers[0])
print(user.name)
print(user["active"])

Constants and annotations

const PORT = 8080
name: str = "Ada"
tags: str[] = ["go", "snow"]
value: int | nil = nil
value = 7

const prevents reassignment at runtime. Annotations are optional and gradual. A type mismatch reports the name and received type.

Destructuring

[first, second] = [10, 20]
{name, age} = {name: "Ada", age: 36}

Strings

single = "text"
multiline = """line one
line two"""
welcome = f"Hello, {name}!"

04 · Expressions

An expression produces a value. Expressions may be literals, names, calls, indexing, attributes, function expressions, operators, or a conditional expression.

Arithmetic and comparison

Use +, -, *, /, //, and %. Comparisons are ==, !=, <, <=, >, and >=.

whole = 7 // 2
remainder = 7 % 2
ratio = 7 / 2
ready = count > 0

Boolean and nullish operators

and and or short-circuit. not negates a boolean. in checks membership and not in reverses it. ?? uses a fallback only for nil; zero and false remain valid values.

allowed = active and (role == "admin" or role == "owner")
title = supplied_title ?? "anonymous"
print(0 ?? 99) # 0

Access and slicing

letters = ["a", "b", "c"]
letters[0] = "A"
part = letters[1:]
name = profile?.account?.name ?? "anonymous"
item = data?["missing"] ?? "default"

Normal access reports invalid or missing data. Safe attribute ?. and safe index ?[] return nil when the chain reaches an absent value.

Ternary expressions

label = "open" if enabled else "closed"

Only the selected branch is evaluated.

Compound assignment

count += 1
items[0] *= 2
config.timeout ??= 30

05 · Control flow

Conditions

if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
else:
    grade = "keep going"

For and where

for item in items:
    print(item)
for number in range(1, 10) where number % 2 == 0:
    print(number)

where filters before the loop body. Two names receive pairs from dictionaries, lists of pairs, enumerate, or zip.

While, break, continue

remaining = 3
while remaining > 0:
    print(remaining)
    remaining -= 1

Match

command = "help"
match command:
    case "start":
        print("starting")
    case "help", "?":
        print("help")
    case _:
        print("unknown")

Cases run top to bottom. The wildcard must be the only value in its case and must be last.

06 · Functions

Functions are values. Define one with fn, return with return, and pass functions to collection helpers.

fn add(left, right) -> int:
    return left + right

double = fn(value): value * 2
print(add(2, 3))

Parameters and gradual types

fn repeat(word: str, times: int) -> str:
    return word * times

Annotations check arguments, returns, and variables at runtime. Untyped code stays dynamic. Functions can close over surrounding names.

minimum = 10
is_large = fn(value): value >= minimum

map, filter, fold

numbers = [1, 2, 3, 4]
evens = filter(fn(n): n % 2 == 0, numbers)
doubled = map(fn(n): n * 2, evens)
total = fold(numbers, 0, fn(a, b): a + b)

07 · Errors and cleanup

Snow treats a failure as a value that can be caught. Use fail to stop the current operation, try to establish a recovery boundary, catch to receive the failure, and always for cleanup after success or failure.

fn require_name(user):
    if user?.name == nil:
        fail("name is required")
    return user.name

try:
    print(require_name({}))
catch err:
    print(err)
always:
    print("cleanup")

Uncaught errors include file, line, column, and stack trace. Use with resource as name: when the value has a close method; Snow closes it after the body.

with open_resource() as resource:
    print(resource)

08 · Collections

Dictionary operations

settings = {theme: "dark"}
settings.timeout = 30
print(keys(settings))
print(values(settings))
print(get(settings, "missing", "fallback"))

Pair helpers

for index, value in enumerate(["a", "b"]):
    print(index, value)
for left, right in zip([1, 2], ["one", "two"]):
    print(left, right)

zip stops at the shorter list. append, reverse, and sort create useful collection transformations.

09 · Modules and imports

Use using for standard modules and import for Snow files. A module is a namespace whose members are ordinary values accessed with a dot.

using http
using json
response = http.get("https://example.com")
print(response.status)

import ./formatters as fmt
print(fmt.title("snow"))

Top-level values are public by default. priv hides a function or variable from imported exports; pub makes intent explicit. Relative imports may use ./ and ../. Import cycles are detected.

11 · Projects and packages

A minimal project uses snow.toml and src/:

name = "weather_tool"
source = "src"

Use dotted imports for project modules. Keep reusable code in separate files and a small entry point in src/main.snow.

snowball init my_app
snowball search http
snowball get snow/text.snow@^0.1.0
snowball list
snowball info snow/text.snow
snowball outdated
snowball update

snowball installs packages from the official registry, records versions and checksums in snow.lock, and supports local dependencies. Commit the lockfile for reproducible installs. outdated reports locked packages with newer registry versions.

A useful loop is format, check, test, then run:

snowman fmt -w src tests
snowman check src/main.snow
snowman test
go test ./...

13 · Testing and diagnostics

Parser errors mean source cannot be formed into a program. Runtime errors happen during execution. Static diagnostics report undefined names, unused variables, unreachable code, unknown modules, and type mismatches without executing the program.

# math_test.snow
assert(2 + 2 == 4, "addition")
assert("snow".upper() == "SNOW", "text")
print("ok")

Keep tests focused and deterministic. Use try/catch only where recovery is meaningful. The LSP publishes parser and checker diagnostics after documents open or change.

14 · Editor and LSP

The Snow language server uses JSON-RPC over stdin/stdout with standard Content-Length framing. Build it with:

cd LSP
go build -o snow-lsp ./server

The VS Code extension registers .snow, provides the Snowflake icon, starts the server, reports diagnostics, and completes built-ins, modules, and members. After using http, typing http. suggests get, post, put, delete, patch, and request.

cd LSP/vscode_extension
pnpm install
pnpm run compile
npx @vscode/vsce package --no-dependencies
code --install-extension snow-0.1.0.vsix --force

Full synchronization uses didOpen, didChange, and didClose. Hover, go-to-definition, references, formatting, and rename are not currently implemented.

Literal forms

Start with the examples in examples/, then use snow_test.go as executable behavioral documentation. The language is intentionally small: learn the core values and blocks first, then add modules only when the program needs them.
